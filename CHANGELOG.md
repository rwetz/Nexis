## [0.3.0] — 2026-09-08

First release of Atlas, which is the merge of two apps that turned out to be two views of one dataset: **nexis-imagine** (an isometric map of local repos) and **[nexis-dev-dashboard](https://github.com/rwetz/nexis-dev-dashboard)** (a git-status list). Both are archived; their histories are preserved here.

### Added

- **One scan, two views.** The list is branch, sync state, changed files, stashes and last commit for every repo in one table. The map is the same repos as an isometric scene — an atlas where each repo is a plot with a tower per language, and a city you walk into where directories are terraces and file height is lines of code. `v` switches between them.
  - **They were two front-ends over one dataset all along**, which is why they are now one app: the same `Config` shape (`repos` / `scan_root` / `scan_depth`), the same `git2` + `rayon` parallel scan, the same repos on the same disk. Kept apart, they walked every repo twice and carried two drifting copies of the same window chrome.
  - **The selection is shared.** Pick a repo in the list, press `v`, and it is the one the map has marked; drill into a city and switch back, and the list is already on that row. That link is the point of the merge — a merge that only deduplicated code would not have been worth doing.
  - **One `RepoSummary` serves both.** It carries the git half (branch, ahead/behind, counts, stashes, last commit) and the size half (files, bytes, language mix) from a single pass. Ten repos including the full filesystem walk scan in ~270 ms, which is what makes a single unified scan cheap enough that neither view needs its own.
  - The backend orders repos biggest-first because the map's squarified treemap requires descending weight and a stable order stops islands hopping between refreshes; the table sorts its own rows by name, and keyboard selection walks whichever order is actually on screen.
- **`nexis-atlas://` deep links.** Two verbs over one argument — `focus?path=…` selects a repo in the list, `map?path=…` opens its city.
  - **A link can only ever *select* something Atlas already scanned.** The path is matched against the repo list and never handed to the backend, so no link can make Atlas read a directory it would not otherwise have looked at. URLs are parsed and validated in Rust (`src-tauri/src/links.rs`) before the webview sees them, because a URL arriving from another process is untrusted input.
  - **A path *inside* a repo resolves to that repo**, longest match winning, so a submodule beats its parent. Senders routinely know a working directory long before they know which repo contains it.
  - **On Windows the scheme is registered by the NSIS installer only.** The `.msi` installs a working app but writes no `Software\Classes\nexis-atlas` key, so deep links are inert for MSI installs — Tauri's deep-link plugin injects the registration into the NSIS script and not into WiX. Install the `-setup.exe` if you want links to work.
  - `tauri-plugin-single-instance` is what makes this work on Windows and Linux at all: a deep link opens the app with the URL as its only argument, so a second launch hands that argument to the copy already running and raises it, rather than starting a rival.
- **"Open in Nexis"**, in the detail pane and the map inspector — launches [Nexis](https://github.com/rwetz/Nexis) with the repo as its workspace. It rides Nexis's existing launch-argument contract rather than a `nexis://` URL, because Nexis registers no scheme yet. Hidden when no Nexis is found; `NEXIS_BIN` overrides discovery.
- **The config of either predecessor is adopted on first run**, so `scan_root` does not have to be pointed at the same directory a third time. Only a config that still parses is adopted — a corrupt predecessor should not become a corrupt Atlas.

### Changed

- **The design layer moved out into [`@nexis/design`](https://github.com/rwetz/nexis-design)** and is now a dependency rather than a copied snapshot. Atlas keeps only what a dependency cannot be: `styles/globals.css` (the Tailwind v4 entry, and what shadcn's `components.json` points at), a `cn` re-export for shadcn's alias contract, and `public/cursors/` — generated by the package's postinstall and gitignored, because a CSS `cursor: url()` resolves against the document and cannot reach into `node_modules`.
