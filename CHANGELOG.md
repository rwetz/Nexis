# Changelog

All notable changes to Nexis. Format loosely follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow [SemVer](https://semver.org/) (pre-`1.0`, minor bumps may include breaking changes).

## [Unreleased]

### Added
- **Art pack: a palette panel, with contrast checking and the active theme as a starting point.** A new `palette` view under the `art` pack — swatches you can name and edit, WCAG contrast on every one of them, colour harmonies, and export as CSS custom properties, a Tailwind theme fragment, JSON, or an SVG swatch strip. The pack now owns two panels rather than one.
  - **Seeding from the live theme is the thing a browser palette tool cannot do.** `applyTheme` already puts every colour on the document root as a custom property, so **Interface** loads the theme's background/foreground/primary/accent/muted/border/destructive and **Terminal** loads its sixteen ANSI colours. "Start from Aurelian" is a button rather than a copy-paste exercise, and it is the same lever `iconResolver.ts` pulls when it retints the file tree.
  - **Theme colours are resolved through a one-pixel canvas.** A custom property's computed value is whatever the theme author wrote — `#eab308` in one theme, `oklch(0.72 0.19 85)` in another — and `color.ts` deliberately parses hex and `rgb()` and refuses the rest rather than half-parsing it into a wrong colour. The browser already contains a complete CSS Color 4 parser, so the resolver asks it: paint one pixel, read the bytes. (`fillStyle` round-tripping is the tempting shortcut and is not reliable — Chromium hands back `oklab(…)` for wide-gamut input, which leaves you parsing again.) A sentinel detects values the browser rejects, so an unparseable token is dropped rather than reported as black. Verified live against `oklch()`, `color(display-p3 …)`, named colours, and garbage.
  - **Contrast lives here rather than in the Web Dev pack**, where the roadmap had parked it: picking colours and judging them is one activity, and splitting it across two packs would put neither where you are when the question comes up. Ratios are WCAG 2.x exactly — the 0.03928 threshold and the 2.4 exponent are the specification's, not a rounding of something nicer, because a checker that disagrees with every other checker is worse than none.
  - **Ratios truncate rather than round, and that is the point.** WCAG's thresholds sit exactly on one-decimal values (3, 4.5, 7), so rounding 4.47 to "4.5:1" puts a passing-looking number beside a failing badge — and the number is what gets believed. Found by looking at a real palette, where a swatch read `4.5:1` and graded fail. Truncation can only understate, so the figure and the grade can never contradict each other; a property test sweeps the range to keep it that way.
  - **Harmonies rotate hue in HSL, on purpose.** A perceptual space is the better answer for interpolation, but harmonies are defined as rotations on the classical colour wheel and that wheel is HSL's hue circle — rotating 120 degrees in OKLCH gives a defensible colour that is not the triad anybody means. Monochromatic is the one exception to "the base comes first": it is a lightness ramp, and a ramp is only usable as a scale if it is ordered, so the base sits mid-scale.
  - **Generating a harmony appends rather than replaces.** Replacing is the obvious implementation and it is wrong: entries persist the moment they change, so one mis-click would have destroyed a sixteen-swatch palette with no undo. A palette is a collection you build up — unlike the playground's single document, where replacement is the point. Colours already present are skipped, so pressing the same button twice does nothing instead of growing duplicates.
  - Export names are slugged per format, and **collisions are numbered rather than silently overwriting** — losing a colour because two of them were called "Blue" is a bug you find much later, in the stylesheet. Swatch names are escaped in the SVG output, which is a complete document like everything else the pack emits, so it goes straight into the playground and the raster exporter.
- **Art pack: PNG export, and writing art to the workspace.** The pack could only ever put text on the clipboard, which made it the one part of the Art preset that never touched the filesystem — despite that preset being scoped to "source control, file manipulation, art". The export bar now offers **PNG** alongside SVG/JSX/`data:` URI, at 1x-4x over the document's intrinsic size (with the resulting pixel dimensions shown), and a **Save** control that writes `name.svg` or `name.png` into the open workspace folder.
  - **PNG is a render, not a fourth string transform, and that has a consequence worth stating.** Rasterizing goes through an `<img>` — the safe path, since an SVG loaded as an image runs with no script and no external fetches — but an `<img>` is an **isolated document**, and the page's custom properties do not cascade into it. That is pitfall #18's constraint arriving from the other direction: the file-tree art must be inlined because `var(--terminal-ansi-*)` cannot reach a `data:` URL, and for the same reason `currentColor` cannot reach one here. `currentColor` in an isolated document falls back to the initial value of `color`, which is black — so every themed icon in this app would have exported as black-on-transparent: fine on a light background, invisible on a dark one, with nothing saying why. The colour is therefore resolved *into the markup* before rasterizing, `svgToPngBlob` takes a colour rather than inferring one, and the bar grows a colour control (seeded from the theme's own resolved foreground) the moment a document that needs it is selected.
  - **The intrinsic size is computed, not read.** An `<img>` with an SVG source has no intrinsic size unless the document carries absolute `width`/`height`; icon art usually carries only a `viewBox`, and Chromium then lays out the replaced-element default of 300x150, cropping the export without an error. Two bugs in that computation were found by *running* it rather than by reasoning about it, and both now have regression tests: `\bwidth` matches inside `stroke-width` (a hyphen is a word boundary), and scanning the whole document finds the first child carrying a `height` — together they reported a 24-unit icon as 1.5x18 and exported a sliver. Only the root start tag is searched now, and an attribute name must be preceded by whitespace or a quote.
  - **Saving reuses the audited write path.** A new `fs_write_file_bytes` command exists because `fs_write_file` takes a `String` and a PNG is not one — routing image bytes through UTF-8 would corrupt them silently. Everything else is deliberately shared with it: the same `resolve_path`, the same `write_path`, so binary writes inherit the atomic staging *and* the WSL `mv` fallback (pitfall #17) rather than growing a second, unaudited write path. A 64 MiB cap bounds what one IPC call can be asked to allocate.
  - Saving an SVG writes the **raw source**, never the JSX or `data:` URI form — those exist for pasting into code and neither is a valid `.svg` file. Filenames are sanitized to a single safe path segment, and a failed save states why and stays on screen rather than auto-hiding.
- **Art pack: the SVG playground can be edited with the mouse.** A new **Canvas** tab beside Source, Shapes and Presets. Click a shape to select it, drag it to move it, drag the dots to move individual points — a path's anchors *and* its bezier control handles, a rect's corners and corner radius, a circle's radius, a polygon's vertices, a line's endpoints — and drag a bounding-box corner to scale (uniform by default, Shift to stretch). Arrow keys nudge, Delete removes, Escape deselects. Every gesture ends in a rewritten `d`, `x` or `points` attribute in the same document the code pane holds, so there is no second model to keep in sync and no mode to leave.
  - **The click has to be traced back through the sanitizer, and that indirection is not optional.** The preview renders a *sanitized* copy, because this is a Tauri webview with `window.__TAURI__` in scope and SVG can carry script. So a click lands on a node in the sanitized render, not in the user's document. `lib/svgDoc.ts` tags every element `data-nx-id` before sanitizing, and that id is what maps the hit back to the node to mutate. Rendering raw source to make selection simpler would trade the pack's whole security posture for a saved indirection.
  - **Your formatting survives.** The document is parsed with `DOMParser` and mutated as a tree, and every mutation writes an attribute rather than restructuring — so `XMLSerializer` hands back the same indentation and line breaks it was given. Two normalizations are imposed and both are pinned by tests: `<rect />` becomes `<rect/>`, and whitespace between attributes inside a start tag collapses, so a hand-wrapped multi-line `<svg …>` header re-joins onto one line. Element indentation and blank lines survive, and none of it is paid until something is actually edited. An editor that reflows the whole file the first time you nudge a rectangle is an editor people stop using.
  - **Primitives move by their own geometry, not by an accumulated transform.** Dragging a rect rewrites `x`/`y`; dragging a path rewrites every coordinate in `d`. Only the cases with no geometry of their own (groups, `<use>`, text) fall back to a `transform`, and that merges into any existing translate — without the merge a drag appends one per pointer move and a second of dragging leaves a kilometre-long attribute that is correct and unreadable.
  - **Three coordinate spaces, kept apart on purpose.** Client pixels, the element's own user space (where `x`/`cx`/`d` live), and its parent's space (where a transform translate lives). A move measures its delta in the *parent's* frame — using the element's own would double-count its transform every frame — and a scale freezes the screen matrix at pointerdown, because writing a transform changes the live matrix and reading it back would feed the scale into its own input. A scale also re-derives from the source as it stood at pointerdown rather than compounding: twenty frames of 1.1x is not 2x, and a compounding drag can never be dragged back to where it started.
  - **The overlay lives in the art's own coordinate system, and the canvas is `zoom-exempt`.** The selection box and handles are drawn into an SVG that mirrors the art's `viewBox` and aspect-ratio handling, positioned over the same box, with every position mapped by a matrix *ratio* (root-inverse times node) so any factor the two share — an ancestor CSS zoom, the device pixel ratio, the viewBox fit — cancels rather than needing to be measured and divided away. The viewport is `zoom-exempt` for the same reason the terminal, the REPL and every CodeMirror instance are (pitfall #15): under `zoom: var(--app-zoom)` the geometry APIs stop agreeing with the pointer coordinates they are compared against. Guarded by a new `pitfall 15 (canvas)` tripwire.
  - `pointer-events: all` on the rendered shapes is what makes an unfilled icon selectable at all — with the default, only the stroke itself is a hit target, and most icon art is `fill="none"`.
  - The path parser (`lib/pathData.ts`) normalizes everything to absolute `M L C Q A Z`, expanding `H`/`V` and reflecting `S`/`T`, because a handle whose position depends on the segments before it cannot be dragged independently. **Arc flags are read one character at a time**: the grammar lets both flags run together with the next coordinate, so `a5 5 0 011 1` is a valid and commonly emitted spelling that a generic number scanner reads as `011` and turns into a silently corrupt arc. A half-typed path returns the segments understood so far rather than throwing, since live editing means truncated input is the normal case.
- **Art pack: a preset gallery, and eight more shape generators.** A **Presets** tab with 27 ready-made documents in four groups — Marks, Shapes, Patterns, Dividers — because a blank document is the worst starting point a drawing tool can offer and the playground shipped with exactly one starter. Picking one drops it into the editor as ordinary source and lands you on the canvas to adjust it; no preset is a special case, and nothing tracks where a document came from.
  - Half the presets are hand-authored on the 24-unit grid with a 1.5 stroke that the 16/24/32/64 preview row exists to judge. The other half are **generator output frozen at a good parameter set**, so a preset over a generator is a name and four numbers rather than a second copy of the geometry — and when a generator improves, its presets improve with it. Unstated parameters fall back to the generator's defaults, so adding a slider later does not silently break the presets over it.
  - The new generators: **star**, **polygon** (with rounded corners), **gear**, **spiral**, **rings**, **dot grid** (with a radial falloff), **burst** and **chevrons** — taking the set from six to fourteen. Angles are measured from twelve o'clock rather than from SVG's own three-o'clock zero, applied once in a shared helper: nobody dialling "Rotation" on a star expects zero to mean "one point aimed right". The polygon's corner rounding clamps its cut-back to half the shorter edge, without which a large radius on a triangle turns the shape inside out. The gear punches its bore with `fill-rule="evenodd"` rather than painting over it in a background colour, so it stays one path and works on any background rather than only on the one it was drawn against.
  - A test asserts every preset names `currentColor` and no literal hex — art with a baked-in colour cannot take the theme, which is the same defect pitfall #18 describes for the file-tree icons.
- **A "View onboarding" button on the welcome screen.** Onboarding was effectively one-shot for anyone who dismissed it on day one; this is the way back in, opening the same takeover the command palette does.
- **Art pack: a parametric shape generator.** Six generators — blob, wave, filled wave, arc, divider and grain — with live sliders, sitting as a **Shapes** tab beside **Source** in the SVG playground. Each one is a pure function from numbers to a complete SVG document, so its output drops straight into the editor where the existing optimize, preview and export paths already work; no generator owns a preview or an export of its own.
  - **Randomness is seeded, always.** The naive blob calls `Math.random()` at render time, and that is wrong here in a way that only shows up in use: the preview would differ from the exported markup, the shape would jump on every re-render, and nudging one slider would reroll the whole form so you could never converge on the one you liked. Seed is a parameter like any other — same numbers in, same path out. A test pins it.
  - **Insertion is an explicit button, not live-writing into the editor.** Live-writing reads as more immediate and is worse: it destroys whatever was hand-written the moment a control is touched, with no undo across that boundary. The generator previews its own output instead.
  - The blob is a Catmull-Rom spline converted to cubic beziers rather than straight or quadratic segments, so each jittered radius is actually passed through — a test asserts that at zero variance every on-curve point sits within 0.05 units of the exact radius. The arc sets the large-arc flag past a half turn, without which every sweep over 180 degrees silently draws the short way round.
  - **Grain honours `currentColor` like everything else**, which raw `feTurbulence` does not: turbulence output is opaque RGB static that ignores fill. It is converted to an alpha mask with `feColorMatrix` and composited against a `currentColor` rect, so generated noise themes with the app instead of being the one shape that cannot.
- **The command ledger has a decision record, which is the gate its ROADMAP item named.** `docs/vault/decisions/command-ledger.md`. No code yet — that is the point: eight of the *"terminal-native features an IDE can't have"* sit on this store, and built ad hoc it becomes five incompatible ones. What it settles: an append-only NDJSON metadata log plus **separate** output blobs per workspace, split by deletion cost rather than by speed; **no new dependency**, with SQLite considered and rejected in writing (this repo has no in-process database — the Database panel shells out to the `sqlite3`/`psql`/`mysql` CLIs — and a scan over ~200-byte records answers every gated feature except the output archive, which wants a content search rather than a relational index); redaction **frontend-side before IPC**, following the share-server and diagnostics precedent, because `redactSensitive()` has no Rust counterpart and two copies of a security-critical pattern list drift; private terminals excluded **at the OSC-133 source** rather than downstream, both enforced by tripwires that must land with the writer and before any panel; **"forget this" compacts and never tombstones**, because a tombstoned secret is still on disk until a compaction nobody can promise ran — that single requirement is what chose the storage shape; workspace identity as a normalized path with the git root commit as an *offered* re-association key, never a silent merge; and two independent retention caps that evict output blobs before metadata.
- **Web Dev pack: an HTTP/REST client.** Method, URL, headers, body, and a response view with status, wall-clock time, size, content type and the post-redirect URL; requests and variables are saved **per workspace**, because a `baseUrl` is a property of the project you have open rather than of the machine. Variables use the same `name: value` syntax as the header box (with `#` to comment a line out) rather than inventing a second one, and are referenced as `{{name}}` in the URL, headers or body.
  - **Requests go through a new `http_send` command in `net.rs`, not the webview's `fetch`.** Three reasons in order: `fetch` would apply CORS to a request that has nothing to do with a browser page and fail most of them; `http_send` carries the existing SSRF guards; and it can report timing and the final URL, which `fetch` will not hand back.
  - **It is deliberately a separate command from `ai_http_request`** even though the two share every validation helper. They have different threat models and must be able to diverge: `ai_http_*` is the *agent's* egress, where a URL can originate in model output or a tool result, which is why `allow_private_network` defaults off there. The REST client is driven by a URL a human typed, and reaching `localhost:3000` is the entire point — so private and loopback destinations are allowed here. **What does not relax:** cloud-metadata addresses (169.254.169.254, `fd00:ec2::254`, IPv6 link-local, the metadata hostnames) stay refused regardless of that flag, along with the header blocklist, the userinfo rejection, the scheme allow-list, and the DNS pinning that defeats rebinding between classification and connect. Two new Rust tests pin both halves of that contract, since the AI path shares the same function.
  - An unknown `{{variable}}` is left **verbatim** rather than substituted with an empty string, and the panel names it before you send. Emptying it produces a request to `https:///users` or a header reading `Authorization: Bearer `, and the resulting 401 sends you looking at the server instead of at the request. A header line with no colon is reported rather than silently dropped, for the same reason. A bare `localhost:3000` gets `http://` rather than being parsed as the scheme `localhost` with path `3000`, which is valid and never what was meant.
  - A JSON response is pretty-printed only if it actually parses — a truncated body or an HTML error page served with a JSON content type is shown exactly as it came back, because the raw text is the evidence you need. `+json` suffixes (`application/problem+json`) count as JSON.
- **Web Dev pack: a multi-viewport preview.** The preview pane rendered one frame at whatever size the pane happened to be, which answers no question about a responsive layout. Phone, Tablet and Desktop are now toggles above the address bar, and any combination renders side by side against the same dev server; **Fit** is a real option rather than an absence, and stays the default, because most previewing is one viewport and N frames is N page loads.
  - **The sizes are CSS pixels, not physical device pixels** — 390, 820, 1440. An iPhone 15's panel is 1179 physical pixels wide and every `@media` query in the world reads it as 393; a preview built on the physical number tests a layout nobody will ever see.
  - **One scale for every frame, never one each.** Scaling each frame to fill its own column would render a 390px phone and a 1440px desktop at the same on-screen width, which destroys the only thing a side-by-side view is for. The phone is supposed to look small. Scale is capped at 1 so a narrow selection is never blown up past true size, which would misrepresent text size — usually the thing being checked.
  - Frames scale with `transform: scale()`, **never CSS `zoom`**. Both shrink the box; only transform keeps hit-testing correct. A `zoom` here would reproduce pitfall #15 *inside the previewed page*, where it would get blamed on the user's own app rather than on Nexis. A test asserts this.
  - **The iframe sandbox is now defined once and shared**, rather than copied per frame. The long-standing rationale — `allow-scripts` + `allow-same-origin` for real dev servers, and never `allow-top-navigation*`, which would let a framed page navigate the parent Tauri webview to an attacker origin and expose `window.__TAURI__` — now guards every frame from one place. `PreviewPane.test.ts` was rewritten to match: it asserts there is exactly **one** sandbox definition, that **every** iframe routes through it, and that no inline `sandbox="..."` literal exists. The old test matched the first `<iframe>` in the file and could not have caught a second frame quietly declaring a weaker sandbox, which is exactly the regression worth catching once there is more than one.
- **Web Dev pack: the scratchpad conversions, without the browser tab.** JSON formatting and a JSONPath query, a JWT decoder, base64 and URL codecs, and a regex tester — the small jobs that otherwise mean opening a web tool and pasting your data into it. That habit is the reason this exists as much as the convenience is: **pasting a bearer token into an online JWT decoder is a routine and genuinely bad idea**, and doing it in a panel that makes no network calls is the same gesture without the disclosure. The `web-dev` pack is no longer an empty container.
  - **The JWT decoder says what it is.** It shows the header, the payload, `exp`/`iat` as local times with an expired/expires badge, and the signature — and it states permanently that the signature is **decoded, not verified**, because a decoder that looks like a verifier is how `alg: none` bugs reach production. Verification needs the issuer's key and the algorithm the issuer actually intends, neither of which a scratchpad has. `exp` and `iat` are read as seconds since the epoch rather than milliseconds, which is the mistake that puts every token in 1970 and reports it as long expired.
  - **The JSONPath support is a deliberate subset** — `$`, `.key`, `['key']`, `[0]`, `[*]` — and a query using anything outside it (recursive descent, filters, slices) is **rejected by name** rather than silently returning nothing. Silence reads as "the data did not match" when the truth is "the tool did not understand", and those need different reactions from the person typing.
  - **Base64 handles what actually gets pasted**: text beyond Latin-1 in both directions (`btoa` alone throws above U+00FF), and the URL-safe alphabet with missing padding, which is the normal shape of a token copied out of a browser.
  - Every conversion is a pure, total function returning a result rather than throwing, because all of them run on each keystroke against text that is half-typed by definition. The regex tester advances past zero-length matches — `a*` matches the empty string at every position and `lastIndex` does not advance, so the obvious loop hangs the UI thread — and caps its match list.
- **Art pack: an SVG playground built for icon-scale work.** Browser-based SVG editors are bad at the small, precise art this project keeps needing, and the reason is the preview: showing a mark at 300px answers none of the questions you actually have about it. This renders the same source at **16, 24, 32 and 64px simultaneously**, over a pixel grid with centre guides, so "does this 1.5-unit stroke land on a pixel boundary at 16px" is answerable by looking. It lives in the sidebar under the new `art` pack (which is no longer an empty container) and detaches into a tab with the preview beside the code rather than under it — the same expand/collapse pattern the ML Lab's network diagram established, with the collapse control carried back on the tab because a discoverable expand needs an equally discoverable reverse. The source persists locally, so the panel and the tab are two views of one document.
  - **Export as raw SVG, JSX, or a `data:` URI**, with a live preview of the result and one-click copy. The JSX conversion renames the ~25 attributes React spells differently and leaves anything it does not recognise verbatim rather than guessing a camelCase form the DOM would ignore. The `data:` URI percent-encodes rather than base64s (smaller and readable at this size) and escapes `%` *first*, so the `%23` it produces for `#` is not itself rewritten into something that decodes wrong.
  - **An optimizer that reports real before/after bytes.** It strips XML declarations, DOCTYPEs, comments, `<metadata>` and editor namespaces (Inkscape, Sodipodi, Krita, Figma), collapses whitespace, rounds coordinates, and shortens hex colours — and it is idempotent, so the saving it reports is not a function of how many times you pressed the button. **This is deliberately not SVGO**, which the roadmap named: SVGO plus `css-select`/`css-tree` is a large dependency for one panel, and what is needed here is the icon-scale subset, which is a bounded problem with a testable answer. It does no path rewriting, transform collapsing, or element unwrapping — the places where SVGO earns its size and where a naive implementation silently corrupts art. Swapping it for SVGO later is a change to `optimizeSvg` alone.
  - **The preview renders a sanitized copy.** SVG is not an inert image format — it carries `<script>`, event-handler attributes, `javascript:` URLs and `<foreignObject>` — and the preview has to inline its markup, because `currentColor` and `var(--...)` do not resolve inside a `data:` URL (pitfall #18's reason, from the other direction). That markup lands in a webview with `window.__TAURI__` in scope, and "the user pasted it themselves" is not a security model when the entire point of a playground is pasting art found elsewhere. URL attributes are judged on the **normalized** value — entities decoded, whitespace stripped — because a tab inside the scheme gives a live URL containing no literal `javascript:` for a substring check to find. `<set attributeName="onload">`, which re-adds a handler at runtime after a naive pass has finished, is stripped too. The editor and every export keep the original, and the panel says what the preview is withholding rather than silently showing different art.
- **Onboarding is now one flow: preset, then tour, then a checklist that stays.** Nexis taught itself badly, and the pieces it had were disconnected — the preset picker fired on first run and `WelcomeScreen` listed a few shortcuts, and neither said anything about the AI/agent surface, which is both the differentiator and the least discoverable thing in the app. The preset pick is now step one of onboarding rather than a dialog that merely happens to come first.
  - **A guided tour of four to six coach-marks** runs once after the preset is chosen, and it **spotlights only panels that preset actually enabled** — touring a feature that is switched off is worse than not touring at all, so steps are filtered by pack and then filtered again by whether their anchor is on screen, rather than pointing at nothing. It leads with the agent surface: people already know what a terminal is. **It is deliberately not a modal.** Nothing traps pointer events, the highlight ring is `pointer-events: none`, and the app stays usable underneath. That is a direct reaction to the E2E failure this feature had to wait behind — a first-run surface that covers the whole viewport is one that can wedge the suite. Escape closes it and it carries an accessible name.
  - **A persistent "Getting Started" checklist** lives in the sidebar as a core view (never pack-gated: a Bare-Bones user has the fewest packs and the most need of it), is pinned to the rail by default and promoted once into existing users' rails, and is re-openable from the command palette forever. It is the load-bearing half — it survives dismissal, which a tour does not, and it is what still works for someone who skipped everything on day one. Each entry carries a one-line *why* rather than a restatement of its label, its keybinding where it has one, and a row that performs the step.
  - **The checklist is a function of configuration, not a snapshot of first run.** Both it and the tour derive from `enabledPacks` on every render, so changing the preset later in Settings → Features re-derives them instead of orphaning them — a Bare-Bones user who switches to Everything gains the steps for the panels they just turned on. Only *progress* is persisted, and unknown ids are kept rather than pruned, so turning a pack off and back on restores ticks the user already earned instead of resetting them.
  - **Steps complete from wherever the user did the thing**, not only from the checklist: opening the agent (however it was opened), running a command to completion, opening a workspace, and quick-open all signal it. The seam is a DOM event with a single listener that owns the preference write, so no module needs the settings store on its hot path. Steps the app cannot observe from a distance keep a manual checkbox. Progress persists through `writePref()`, so it syncs across windows (pitfall #2).
- **Three domain packs — Web Dev, Mobile and Art — plus icons on every pack and preset.** The pack taxonomy in `src/lib/packs.ts` was organized entirely by *tool kind* (navigation, code tools, dev tools), which is a useful axis for someone already inside the app and a useless one on first run: nobody opens a new editor thinking "I would like the navigation-plus pack". These three are organized by *what you are building*, the axis `ml-lab` already sat on. They ship as real, toggleable containers with no panels yet — the taxonomy and the icon plumbing land first, the panels follow one at a time — and Settings → Features labels them "No panels yet" rather than showing a switch that appears to do nothing.
  - **Presets are now first-class data.** `PRESETS` in `packs.ts` carries the id, label, blurb, art and pack list for each of six presets (Bare-Bones, Standard, Web Dev, Mobile, Art, Everything), and both the first-run picker and the Settings → Features preset row render from it — previously each kept its own hard-coded list of three, free to disagree. `PACK_PRESETS` is derived from it rather than maintained beside it. A preset remains nothing but starting values for `enabledPacks`: no second concept, no state of its own. The domain presets build *on top of* Standard's packs rather than replacing them, because someone building a web app still wants the build runner and the debugger.
  - **`PackDef` gained an `icon: IconName`**, resolved through `src/components/icon.tsx` like everything else, so the plugin contract keeps naming an icon rather than a vendor object (pitfall #18).
  - **The icon registry now carries Nexis-drawn art alongside vendor glyphs.** `REGISTRY` was typed `Record<string, PhosphorIcon>`, which quietly made "an icon" and "a vendor export" the same thing. The first-run preset cards are the case that broke it: a preset is chosen once, at card scale, next to five alternatives, and a general-purpose glyph drawn to read at 16px in a toolbar says nothing about the choice. Six marks are drawn for the job in `src/components/icon-art.tsx` — one 24-unit box, the stroke rhythm of the Phosphor set they sit beside, `currentColor` throughout, `weight` honoured so the resting→active pair still works. Widening the registry rather than dropping a one-off inline `<svg>` at the call site keeps the choke point intact: art is still reached as `<Icon name="preset-web-dev" />`, still sized from the scale. That module deliberately does not import the icon vendor, so pitfall #18's guard still reserves that import for `icon.tsx` alone.

- **npm-installed language servers were found by the probe and then failed to spawn on Windows.** Installing `vscode-langservers-extracted` gave Nexis a working CSS/HTML/JSON server that it still refused to start, and the missing-tools notice told the story backwards: pressing refresh cleared the entry, then opening a `.css` file put it straight back. The two sides were asking different questions. `tool_probe` walks `PATHEXT` deliberately — 1.25.0 added that precisely because these servers land as `.cmd` shims — but the spawn in `lsp/session.rs` handed the bare name to `std::process::Command`, and Rust's Windows program resolution appends **only** `.exe`; it never consults `PATHEXT`. So `vscode-css-language-server` resolved for the probe and did not exist for the spawn.
  - `tool_probe`'s PATH walk now returns the resolved path instead of a bool (`tools::resolve_on_host`), and both the LSP client and the DAP client spawn that path rather than the bare name. One walk answers both questions, so the two cannot drift apart again. When resolution finds nothing the bare name is still passed through, leaving the failure path — and its error message — exactly as it was.
  - **PATHEXT spellings are now tried before the extensionless one**, and that ordering is the fix, not a detail. npm's shim writer emits three files per bin: `foo.cmd`, `foo.ps1`, and an extensionless `foo` that is a *bash* script for MSYS/Git Bash. Preferring the bare spelling — which the old suffix list did — would have resolved to a path `CreateProcessW` cannot execute, turning a lookup miss into a spawn failure. Trying PATHEXT first selects the `.cmd`, which `Command` routes through `cmd.exe` with its own hardened quoting.

  - **A `.cmd` server is not the process Nexis holds a handle to**, so stopping it needed a tree kill. Rust's std spawns a batch program as `cmd.exe /d /c "<shim> ..."` — the handle is the wrapper and the server is a grandchild, so `Child::kill` (a bare `TerminateProcess`) left the server alive holding both pipe ends: the reader thread never saw EOF and every restart leaked another orphan. LSP and DAP sessions now hold a Windows Job Object with `KILL_ON_JOB_CLOSE`, the same guard ConPTY children have always had — the primitive moved from `pty/job.rs` to `modules/job.rs` and is now shared rather than duplicated.   - **Resolution now answers the question the spawn asks, not an approximation of it.** Three ways it could return a path that would not run: a set-but-empty `PATHEXT` reads back as `Some("")` rather than absent, so the `.COM;.EXE;.BAT;.CMD` default never fired and the suffix list collapsed to the extensionless spelling — silently disabling `.cmd` lookup altogether; a program named as a *path* (`.\node_modules\.bin\js-debug-adapter`, which the debugger panel invites) skipped the suffix walk entirely and matched npm's extensionless bash script sitting next to the shim; and on Unix `mode & 0o111 != 0` accepted an exec bit belonging to somebody else, so a root-owned `0700` copy early on `PATH` would shadow the `0755` one later, where `execvp` skips the `EACCES` match and keeps walking. The suffix parsing is now a pure function tested on every platform rather than only on a Windows runner, and Unix executability is `access(X_OK)`.

## [1.25.0] — 2026-08-19

### Added
- **The System Monitor's sampling rate is now a control, not a constant.** It polls once a second — the value was hard-coded in `useSystemMonitor`'s default and nothing surfaced it, so the only way to learn it was to read the source. A four-step switcher sits next to the load average: **100 ms / 200 ms / 500 ms / 1 s**, persisted as the `sysmonIntervalMs` preference through `writePref()` so it survives a restart and syncs across windows (pitfall #2). 1 s stays the default, so nothing changes for anyone who doesn't touch it. The trade is real in both directions and each step's tooltip states it: the chart history is a fixed 128 samples, so 100 ms buys detail over a ~13-second window where 1 s covers ~2 minutes — and every sample re-walks the whole process table, so the fast steps cost measurable CPU on the machine you are measuring. Stored values are snapped onto the allowed steps on load, so a hand-edited config cannot ask for a 1 ms poll.
- **The ML Lab's network diagram can be opened as its own tab.** In the sidebar rail the drawing had 220 px of height to place every input feature, hidden unit and class in, which is enough for a toy model and nothing else. It is the same live view, not a snapshot — architecture, feature names, class labels and learned edge weights are read from the project and the ML store, so it keeps updating as training runs. The tab's header carries a collapse button back to the panel: expanding is discoverable from an icon, so collapsing has to be too — hunting for the tab's close control is not the same gesture. ### Fixed
- **Committing from the Source Control panel reported "author identity unknown" and then threw the fix away.** ([#47](https://github.com/rwetz/Nexis/issues/47)) Git's own message for an unconfigured identity is a twelve-line block whose useful half is the two `git config` commands in the middle of it. Nexis passed that through as an untyped `CommandFailed`, and the panel's feedback line renders with `truncate` — so the user got `git commit failed: Author identity unknown...` on one clipped line and the remedy was cut off the end. It also auto-hid after 3.6 seconds and was `pointer-events-none`, so it could not be read at leisure, selected, or copied.
  - The condition is now classified into a typed `GitError::IdentityUnknown` in `ensure_success`, next to the existing auth classification. That is the funnel every git command passes through, so `stash`, `merge`, `revert` and `cherry-pick` — all of which write a commit object and fail identically — are covered, not just `commit`. Five stderr markers are matched rather than one exact phrasing, because git words the same condition differently depending on whether nothing is configured, `user.useConfigOnly` disabled auto-detection, or a name is configured as an empty string.
  - The message names both commands and, crucially, says **which machine to run them on**: a WSL workspace reads the distro's `~/.gitconfig`, not the one on Windows, which is the trap the report came from. Setting an identity on the Windows side of a `\\wsl.localhost\...` workspace changes nothing.
  - Panel errors no longer auto-dismiss, wrap instead of truncating, are selectable, and carry a dismiss button. A success notice still fades after 3.6 s and still ignores pointer events so it cannot eat clicks on the controls beneath it. An error is something to act on, and several of them carry the exact command that fixes them — a 3.6-second window to read and retype that is not a window at all.
- **Switching a workspace into WSL could leave a terminal with a cursor and no prompt, and it was the distro's boot log doing it.** `switchWorkspace` asks the distro for `$HOME` before anything else, so on a cold distro that probe is the `wsl.exe` call that starts the VM — and with systemd enabled, `wsl.exe` relays the entire boot to the probe's stdout. The reader took the last non-empty line, which is wrong in both directions: `printf %s` emits no trailing newline, so an unterminated console line swallows the value, and printk keeps arriving *after* boot hands off. In a real capture (Ubuntu 26.04, systemd 259.5, `debug` on the kernel command line) `hv_balloon` logs at t=4.19s, `misc dxg` at 4.65s and 5.07s, and a WSL `CheckConnection` error at 7.36s — all after `graphical.target`, all candidates to be read as the home directory. The bad value then became the new terminal tab's cwd, `pty_open` rejected it as "cwd not accessible", and the frontend swallowed the rejection into a `console.error` — so the whole failure rendered as pitfall #1's blank terminal. It reproduced on the *second* switch rather than the first because WSL shuts the VM down on idle, so going Windows -> WSL -> Windows -> WSL is what finds a cold distro.
  - Every WSL probe now emits its answer wrapped in sentinels (`workspace::wsl_probe_script`) and reads it back by locating them (`parse_wsl_probe` / `parse_wsl_probe_path`), which boot output cannot forge. A second, independent guard requires the answer to be POSIX-absolute — nothing in a boot log starts with `/`. This covers `wsl_home`, `wsl_login_shell` (a garbage value there became `--exec <kernel log line>`, which exits instantly — the same blank terminal from the other direction), the WSL `ZDOTDIR` probe, and `py_detect_envs`' distro interpreter lookup. The parser is deliberately platform-independent so its tests, including a fixture built from the real capture, run on every platform rather than only on Windows.
  - `switchWorkspace` refuses a WSL home that is not a Linux path and says what the distro answered, instead of resetting the workspace onto it. `--cd` applies the same rule before handing a path to `wsl.exe`. `wsl --list --verbose` rows now require a numeric VERSION column, so console noise cannot register as a distro (checking VERSION rather than STATE keeps it locale-safe — WSL translates the state words, not the number).
  - **A rejected `pty_open` is now shown in the terminal**, not only in the devtools console. Every rejection used to render identically to a working shell that had printed nothing, which is precisely why this went undiagnosed.
  - Documented as pitfall #21 in CLAUDE.md, with the `pitfall_21_wsl_probes_parse_by_sentinel` tripwire: it fails if the positional reader returns, if a `run_wsl_sh` call builds its script without `wsl_probe_script`, or if a file emits the sentinels without parsing them back. It reads balanced call expressions rather than single lines, because rustfmt reflows these calls as soon as an argument grows.
- **Every `cd` in a terminal tore the pane off its renderer slot and reset the buffer.** The pane-tree leaf's `cwd` is rewritten by `setLeafCwd` on every OSC 7, and `useTerminalSession` listed that value in the dependency array of the effect that binds the leaf to a renderer slot. So a directory change ran the whole teardown: serialize the buffer, release the slot, `term.clear()` + `term.reset()`, replay the snapshot, and hide the host for two animation frames. `ensureSession` only reads the value when it *creates* the session, so the dependency bought nothing and cost a full reset — visible as a flicker, and as a lost prompt when the serialize landed between the OSC 7 and the prompt bytes (zsh and bash emit the cwd from `precmd`, *before* the prompt is drawn). The value is mirrored into a ref instead. This was invisible in WSL until shell integration actually installed into the distro — before that fix a WSL terminal emitted no OSC 7 at all, so the leaf's `cwd` never moved and the effect never re-ran, which is why it surfaced as a WSL-switching bug. Guarded by two `pitfall 22` tripwires in `src/lib/pitfall-guards.test.ts`.
- **The zsh shell integration never loaded the user's own config if they set `ZDOTDIR`.** The Rust side exports `NEXIS_USER_ZDOTDIR`; all four zsh scripts read `TERAX_USER_ZDOTDIR`, a name left over from the fork. The lookup fell through to its `$HOME` default, `$HOME/.zshrc` does not exist for anyone who moved their config, and the shell came up with the bare built-in prompt — the user's theme, aliases and history settings simply absent. WSL felt it hardest, since probing the distro's `ZDOTDIR` is the only reason the value is computed there at all. The scripts' internal identifiers moved to the `_nexis_` / `__NEXIS_` prefix at the same time, matching `profile.ps1`, which had already been renamed.
- **Terminal environment variables and truecolor detection did nothing inside WSL.** A WSL session's child process is `wsl.exe`, and Windows environment variables do not cross into the distro without `WSLENV` or an explicit Linux-side assignment. `TERM`, `COLORTERM` and `NEXIS_TERMINAL` were set on `wsl.exe`, and so were the user's own variables from **Settings -> General**; none of them reached the shell. Programs inside a WSL terminal therefore saw no `COLORTERM` at all and fell back from truecolor. All of them now travel as `env NAME=VALUE` arguments in the `--exec` prefix, which the zsh branch already used for `ZDOTDIR`. Motion was the same problem from the other side: two `cubic-bezier()` values existed in the entire codebase, one of them Material Design's stock curve, and everything else took whatever Tailwind and tw-animate-css default to. A UI assembled from defaults looks like every other UI assembled from the same defaults.
  - **Every icon now goes through one semantic choke point.** `src/components/icon.tsx` maps app vocabulary (`"close"`, `"refresh"`, `"git-branch"`) onto glyphs; call sites write `<Icon name="close" />` and never name a vendor. That is what collapses the 24 duplicate concepts — there is one `"refresh"`, and it is one glyph — and it makes the vendor swappable in one file instead of 104. Sizes come from a 5-step scale (`xs` 12 / `sm` 14 / `md` 16 / `lg` 20 / `xl` 24) and active state is expressed as `active` rather than a hand-picked stroke.
  - **The UI icon set moved from Hugeicons to Phosphor**, which ships six weights from one package. That weight axis is the reason it was chosen over a flat set: `regular` is the resting state and `fill` marks active/selected, so state is encoded in the glyph itself rather than in colour alone. **The bundle got smaller, not larger** — the main chunk dropped from 875.50 kB to 744.03 kB (250.59 → 217.17 kB gzipped), because 128 tree-shaken per-icon components weigh less than the vendor's 160 bundled icon-data objects.
  - **Motion is now derived from Nexis being a terminal.** Tokens in `globals.css` define an asymmetric pair of curves (leaving accelerates away, arriving decelerates hard into place; neither overshoots — nothing in a tool should bounce) and three durations scaled by how far a thing travels: `--dur-tap` 90 ms for in-place changes, `--dur-panel` 140 ms for collapsibles and popovers, `--dur-window` 200 ms for dialogs. Crucially these are wired into Tailwind's `--default-transition-duration`/`--default-transition-timing-function`, so the hundreds of call sites that never named a duration inherit the house curve rather than only the handful that did. The two most-seen animations were replaced outright: indeterminate progress **ticks through four discrete quarter-turns** (`.nexis-spin`) instead of sweeping smoothly, because a terminal spinner has always been a character cycling in its cell and can only ever be discrete; and live/pending indicators **blink at a VT100 cursor's ~1.06 s cadence** (`.nexis-blink`) as a near-square wave instead of Tailwind's sine-eased `animate-pulse` breathe. Both degrade correctly under `prefers-reduced-motion` — the spinner holds a static glyph and the blink settles at a dimmed-but-visible opacity, so a live indicator is still distinguishable from an idle one.
  - **The file tree wears the active theme's palette instead of Catppuccin's.** This fixes a real defect introduced alongside the six original themes in 1.22.0: the icon art has its colours baked in, so opening Aurelian (warm gold over deep umber) still produced a lilac-and-macchiato-blue file tree, and no theme could reach it. The whole 659-icon set turns out to be drawn from exactly **19 hex values**, so retinting is a lookup rather than art work — each accent maps to the *same hue role* in the theme's own 16-colour ANSI palette, so a language stays identifiable at a glance and only the shade changes. The mechanism is the interesting part: the substitution emits `var(--terminal-ansi-*)`, which forced the art to be **inlined into the document** rather than served as a `data:` URL, since a data URL is an isolated document that the page's custom properties do not cascade into. Inlining also means a theme switch recolours the tree with no cache to invalidate and no re-render to force. The vscode-icons fallback art is deliberately left alone — those entries are brand marks (NuGet, Maven, Flutter), and a logo recoloured to fit a theme is simply a wrong logo.
  - **AI providers show real brand marks.** Twelve of eighteen now render an actual logo rather than an approximation — notably `zai`, which was a generic sparkle, and `cerebras`, which was a CPU glyph. Nine marks are embedded as path data from **simple-icons** (CC0-1.0, ~11 KB, no runtime dependency); three more come from Phosphor, which ships OpenAI, X and Apple logos. The obvious candidate for this, `@lobehub/icons`, was rejected after installation: it peers on `antd` and `@lobehub/ui` and depends on `antd-style` (emotion) plus `lucide-react`, dragging an entire second design system and a second icon library in beside Tailwind and Phosphor for the sake of nine logos. Providers with no available mark keep a deliberately apt generic (Groq → flash, `openai-compatible` → plug) rather than an invented logo.
  - **The plugin API no longer names an icon vendor.** `PanelContribution.icon` was typed as a Hugeicons icon object, which meant a plugin could not contribute a sidebar panel without depending on the exact icon package Nexis shipped that release. It is now an `IconName` string, so changing the icon package is an edit to a registry rather than a break in a published contract.
  - Documented as **pitfall #18** in CLAUDE.md and guarded by two tripwires in `src/lib/pitfall-guards.test.ts`: one fails the build if any module outside `icon.tsx` imports the icon vendor, the other if `iconResolver` goes back to building `data:` URLs (which would silently un-theme the whole file tree). Both were verified to fire by deliberately reintroducing each violation.

### Fixed
- **Switching workspace by path now updates the workspace environment, so git and file operations run in the right place.** Every git and fs IPC call stamps `currentWorkspaceEnv()` onto its payload, and the Rust side reads it to decide whether to shell through `wsl.exe` or run natively. Only the status-bar environment picker ever set that value: `switchWorkspacePath` — the function behind Recent Workspaces, opening a worktree, and profile-root switching — reset the entire workspace without touching it. Opening a WSL repo by path therefore left the environment on `local`, and the backend ran Windows `git.exe` against a `\\wsl.localhost\…` UNC path, reading the Windows `.gitconfig` instead of the distro's. The visible symptom was `git commit` failing with "author identity unknown", but the mismatch applied to *every* operation in the panel, and to file reads and writes besides. The environment is now derived from the path itself: a `\\wsl.localhost\<distro>\…` or `\\wsl$\<distro>\…` prefix selects that distro, a drive-letter path selects Windows, and a bare POSIX path keeps the distro already in use (the only reading that means anything, since such a path names no distro of its own).
- **The Submodules section was unreachable in every repository.** `SubmoduleSection` fetched its list only once `expanded` was true, but returned `null` whenever the list was empty and the section was collapsed — which is the initial state. The toggle that would set `expanded` lived inside the JSX that was never rendered, so the section rendered nothing, loaded nothing, and rendered nothing again. It now loads on mount, which is what the visibility rule needed all along: the section hides itself only once it knows the repo genuinely has no submodules. Its `catch` no longer swallows failures either — `submodule_status` already maps a missing `.gitmodules` to an empty list on the Rust side, so anything reaching the handler is a real error.
- **The app icon is the Nexis logo again.** Every entry in `tauri.conf.json`'s icon list — taskbar, window, installer, and the macOS/iOS/Android sets — was generated from `src-tauri/icons/nexis-icon.svg`, a purple gradient plate with a `>` caret, rather than the silver interlaced-knot mark. This is the third time a generated placeholder has displaced the real logo, and the first time it survived in the OS icon rather than the frontend: the three in-app `<img>` sites were corrected back in 1.23.0, which made the app *look* fixed while the icon Windows actually shows stayed wrong. The set is now generated from a vector master (`assets/nexis-logo.svg`) instead of the 512×512 raster, so every size down to 32×32 is rendered rather than resampled. The master is a trace of the original artwork and carries faint mottling in the dark plate at 512 px and above, from the tracer quantising the source's vignette; it is not visible at 256 and below.
- **Branch switching and the stash list were broken outright by a NUL byte in the git command line.** Two `--format` arguments were written with the Rust escape `\x00` where git's own escape was needed, which put a literal NUL *inside a process argument*. Arguments are NUL-terminated C strings, so `Command::spawn` rejected both with `InvalidInput` ("nul byte found in provided data") and git never ran — on every platform, not just Windows. `git for-each-ref` powers `branch_list`, and `checkout_branch` validates against it before switching, so the branch dropdown surfaced `failed to spawn git: nul byte found in provided data` and switching was impossible. `git stash list` failed the same way but silently: `stash_list` only called `ensure_success` when `exit_code != 0` **and** stdout was non-empty, and a failed spawn produces empty stdout, so the error was skipped and an empty list returned — which `StashSection.tsx` then rendered as "No stashes yet" via a bare `catch {}` commented "just no stash list — ignore". Stashes were being created correctly the whole time; the list simply never read them. The escape differs by format family and both are now verified against real git: `%x00` in a pretty format (`git log`, `git stash list`), `%00` in a ref format (`git for-each-ref`). The two pieces of padding that hid this are gone as well — `stash_list` now checks `ensure_success` unconditionally, and the stash panel surfaces load failures instead of swallowing them. Documented as pitfall #16 in CLAUDE.md and guarded by `pitfall_16_no_literal_nul_in_git_cli_args`, which fails the build on any production line carrying both a `"--` flag literal and a literal NUL escape.
- **Renaming a file inside a WSL distro no longer fails with "os error 17".** `fs_rename` resolved both paths to `\\wsl.localhost\<distro>\…` and called `std::fs::rename`, which is `MoveFileExW` on Windows. The WSL 9P redirector rejects that call with `ERROR_NOT_SAME_DEVICE` — error 17, which reads like the Linux `EEXIST` of the same number and made this look like a spurious "already exists" — even when both paths are in one directory. The rename is now retried through `wsl.exe --exec mv`, keeping the operation on the Linux side of the share where it is an ordinary atomic `rename(2)`. The in-process attempt still runs first, so a WSL workspace rooted under `/mnt/<drive>` (which maps to a native Windows path) keeps the fast path, and a stopped distro cannot break a rename that would otherwise have succeeded. Fixes #46.
- **Saving a file inside a WSL distro no longer fails with "os error 17" either.** The `ERROR_NOT_SAME_DEVICE` rejection that broke renaming (above) broke every *write* through the same mechanism, and only the rename half had been fixed. `fs_write_file` stages content in an O_EXCL tempfile beside the target and commits it with a rename; on Windows that commit is `MoveFileExW`, which the 9P redirector refuses even though staging file and target sit in one directory. So editing any file under `\\wsl.localhost\<distro>\…` failed at save — and with it AI file writes, theme files, ML run notes and config, and the workspace notes panel, all of which route through that one command. The commit is now retried through `wsl.exe --exec mv`, which performs it inside the distro as an ordinary atomic `rename(2)`. The staging file's Linux path is derived by grafting its generated name onto the target's Linux directory (the host side of that path is a UNC string that means nothing inside the distro), and a target that is not a POSIX absolute path is refused rather than handed to `mv`, so a workspace mislabelled as WSL cannot turn a save into a `mv` of a drive path. The failed in-process attempt hands the staging file back still on disk, so the fallback commits the bytes already written rather than staging them twice, and a failed `mv` removes it. Ordering matches the rename fix: the in-process attempt runs first, so a workspace rooted under `/mnt/<drive>` keeps the fast path and a stopped distro cannot break a save that would otherwise have succeeded.
- **Tab, pane, and terminal-session bookkeeping no longer depends on React running a state updater synchronously.** Eleven call sites in `useTabs.ts` used `setTabs(curr => …)` as a way to *read* the current tab list, assigning to an outer `let` from inside the updater and then reading that variable on the line after `setTabs` returned. React does not guarantee an updater runs synchronously at dispatch — and it explicitly reserves the right to invoke one more than once — so this was correct only by accident of the current scheduler. The consequences were not cosmetic: `closeTab` and `closePaneByLeaf` collected the leaf ids to `disposeSession()` inside the updater, so a deferred invocation would have leaked the PTY session and its snapshot file for every closed terminal; `closeActivePane` *returned* a boolean set inside the updater, which callers use to decide whether the tab itself closed; and the `newMarkdownTab`/`newNotebookTab`/`newImageTab`/`openAiDiffTab` family minted ids with `nextIdRef.current++` inside the updater, so a double invocation would burn two ids and hand back the wrong one. All eleven now follow the pattern three functions in the same file already used: read `tabsRef.current`, compute the next array as a plain value, assign `tabsRef.current` and `setTabs()` together, then run the side effects. The eager ref write also makes the mirror fresher than the post-commit effect alone did, so two tab operations dispatched before a commit no longer see stale state.
- **The file explorer could fire duplicate directory reads, and did it from inside a state updater.** `toggle`, `expand`, and `beginCreate` in `useFileTree.ts` each called `setNodes(curr => { if (…) fetchChildren(path); return curr })` — an updater that returned its input unchanged and existed purely to sniff the current load state, with an IPC call as a side effect. They now read a post-commit `nodesRef` mirror instead. Because that mirror lags a commit where the updater did not, `fetchChildren` additionally tracks in-flight paths and collapses a second request for a directory already being read — which also closes a pre-existing gap the updater form never covered, where a fast double-click on a folder could issue two concurrent `fs_read_dir` calls for it.
- **A `useCallback` in the merge-conflict sidebar sat below an early return.** `ConflictSection` bailed out with `return null` when there were no conflicts, *before* reaching its `resolveWithAi` `useCallback` — so the hook count changed between renders the moment the conflict list emptied, which is exactly the case that happens when you resolve the last conflict. React would then attach state to the wrong hook. The callback is now hoisted above the early return.
- **The new-file dialog's focus timer is cancelled on close.** `NewEditorDialog` deferred its focus-and-select-basename call by a `setTimeout(…, 0)` with no cleanup; a dialog dismissed within the same tick would fire the callback against a detached input.
- **Twenty-six render-phase ref writes moved into effects.** The "latest value" ref — `const xRef = useRef(x); xRef.current = x;` — appeared across the editor pane, the AI panel, the file explorer, the terminal session hook, the global-shortcut hook, the three animated backgrounds, and `App.tsx`, always for the same good reason: to let a listener, rAF loop, or CodeMirror extension read a fresh value without being a dependency that tears the listener down and re-creates it. The mirroring itself was the problem — it happened *during* render, and React is free to discard or replay a render, which would leave the ref pointing at a value from UI that never committed. Every reader in these cases is a DOM event handler, a timer, an animation frame, or a CodeMirror extension, none of which run during render, so mirroring after commit is not just safe but strictly more correct. Two consequences are worth recording for anyone repeating this. Where the mirrored value is rebuilt every render (inline `onCwd`/`onExit` arrows into `useTerminalSession`, inline handler objects into `useGlobalShortcuts`, the composer's `submit`), the effect must be written with **no dependency array at all** — a `[submit]` array on a value with a new identity each render re-runs every time anyway *and* trips `no-effect-with-fresh-deps`, whereas the bare form states the intent exactly. And two of the editor's refs (`openRenameRef`, `openCodeActionRef`) held nothing but a closure over a `useState` setter, which React guarantees is stable — those became one-time `useRef` initializers rather than effects, removing the per-render write entirely instead of deferring it.
  Net effect on the audit: React Doctor's error count for this repo goes from 46 to **0**, across every category, not just Bugs. The 435 remaining findings are all warning-severity and out of scope here.

- **Accessibility pass over forms, overlays and icon-only controls.** Roughly a hundred controls across the panels, dialogs and command overlays were unreachable or unidentifiable without a mouse. Text fields that used a placeholder as their only label — the file picker, shell-history and workspace search overlays, the AI composer, the snippet/template/profile editors, the SQL and ML panels, the process filter — now carry a real accessible name, either an `aria-label` or, where a visible label already sat right above the field (the snippet editor, the rename and PR-description dialogs), a proper `htmlFor`/`id` association. Icon-only buttons — close, dismiss, delete, edit, pin, stash pop/apply/drop, submodule init/update — got names describing the action rather than announcing "button".
  The judgement calls are the interesting part, because the naive fix is wrong in both directions. **Modal scrims and click-outside catchers did not become buttons.** Every one of those overlays already closes on Escape, so the click is a mouse convenience; making it focusable would add a tab stop that announces nothing. They are marked `role="presentation"` — deliberately *not* `aria-hidden`, since these elements wrap the dialog and hiding them would hide the dialog with it. That distinction is not theoretical: an initial pass used `aria-hidden` on the command palette's wrapper and the scan immediately flagged focusable content inside an aria-hidden subtree, which is exactly the bug that change would have shipped. Only the separate dimming layer, which contains nothing, is `aria-hidden`. Two purely decorative surfaces — the animated empty-state folder and the editor minimap — are hidden outright: the folder's click only plays an animation, and the minimap duplicates the scrollbar over a canvas that exposes nothing, so both would have been tab stops leading nowhere.
  Elsewhere the right answer was a composite-widget role rather than a control: the file tree is one tab stop with arrow-key navigation (`role="tree"`), and the refactoring list, recent-files list and connection list are `listbox`/`option` pairs whose rows are selected from a search field rather than tabbed through individually. Three `autoFocus` uses are kept and documented — each lands on the only input of a surface the user just opened, where demanding an extra Tab would be slower, not safer. The close button on a tab and the edit/remove controls on a theme card stay `<span role="button">` because their ancestors are real `<button>`s (Radix `TabsTrigger`, the theme card) and nesting buttons is invalid HTML; they gained the `tabIndex` and Enter/Space handling they were missing, which is the part that actually blocked keyboard users.
  Finally, four rows that wrapped an inline action in an outer control — an AI chat session with its Delete button, a database connection with Remove, a recent file with Remove, a theme card with Edit/Remove — were genuinely broken rather than merely warned about: a `<button>` inside a `<button>` is invalid HTML, and ARIA treats the descendants of an `option` as presentational, so in both shapes the inner control was unreachable by screen reader. Each row is now a plain container holding two sibling buttons — one filling the row for the primary action, one for the inline action — which preserves the layout and makes both reachable. Those inline controls were also `opacity-0` until hover, meaning a keyboard user could focus a button they could not see; they now reveal on `focus-visible`/`focus-within` too. One case is knowingly left alone and documented in place: the Source Control file list is an `aria-activedescendant` listbox whose rows carry Stage/Discard, and the conforming fix is to make it an ARIA `grid` with left/right column navigation — a rewrite of its keyboard handling rather than a relabelling, since changing the roles alone would produce a widget that scans clean while behaving worse.

### Removed

The exemption is scoped to those directories, so dead-code analysis still runs over the rest of `src/`.

## [1.23.0] — 2026-07-20

### Changed
- **Settings navigation moved from a nine-tab strip to a grouped sidebar with search.** The nine sections lived in a single centred `TabsList` in the dialog header — a horizontal row that was already tight at the dialog's 920 px and had no room for a tenth entry, so every new settings section was a layout problem as well as a feature. They now sit in a 208 px left rail, grouped **Application** (General, Features, Themes, Shortcuts) / **AI** (Models, Agents) / **Developer** (Environment, Formatters), with About separated below a rule. Vertical nav scales with the section count instead of competing for width, and the grouping states a relationship the flat strip couldn't: Models and Agents were adjacent but unlabelled siblings before.
  The sidebar's search field is the part that actually changes how the page is used, and it deliberately does **not** match on section names alone. General owns roughly twenty settings under one word — "scrollback", "cursor blink", "OSC 52", "quick terminal" are all invisible to a label-only filter, which is exactly the lookup a settings search exists to serve — so each section carries a keyword list drawn from the setting titles it renders, and typing `api key` reaches Models while `word wrap` reaches General. Enter jumps to the top hit, making search a keyboard-only path (open, type, Enter); it does not clear the query afterwards, so a near-miss can be re-Entered without retyping. Escape clears a non-empty filter before it closes the dialog, since losing the whole dialog on the first Escape is the wrong default when the visible state is a filtered list. Two staleness bugs are handled explicitly: the query resets on close, because a leftover filter would otherwise hide the nav entry for whichever tab the *next* open lands on, and filtering never blanks the content pane — the active section keeps rendering even when its own nav item is filtered out. Sections themselves are untouched; each still renders its own `SectionHeader`, so the content column's header holds only the close button rather than duplicating the title.
- **The panic-lint gate now covers 36 of 40 Rust modules, up from 3.** `#![warn(clippy::unwrap_used, clippy::expect_used)]` previously guarded only the security-sensitive command modules (`net.rs`, `secrets.rs`, `recording.rs`), so a stray `.unwrap()` anywhere else could reach production and abort the process — the release profile is `panic = "abort"`, which makes any unwrap on a bad assumption a hard crash rather than a caught error. Auditing the tree found that nearly every module was *already* free of production unwraps, so enabling the lint across them cost no code changes and locks the property in: CI's `clippy -- -D warnings` now turns a new one into a build failure (verified by temporarily introducing one). Test code may still panic freely — `allow-unwrap-in-tests` in `clippy.toml` covers that. Four modules stay outside the gate because they have real unwraps to convert first, and they're now named in `clippy.toml` and the roadmap rather than left implicit: `fs/file.rs`, `lsp/mod.rs`, `dap/mod.rs`, `pty/session.rs`.

It now uses Radix's `onEscapeKeyDown`, scoped to the search field so Escape from anywhere else still closes the dialog on the first press. `SettingsDialog.tsx` is the first component in the coverage `include` list, and the global floors are ratcheted up accordingly (lines/statements 82 → 84, branches 85 → 86, functions 71 → 73).
- **Git-backed AI checkpoints — one-click revert of an agent edit.** Every `edit`, `multi_edit`, and `write_file` an agent runs is now preceded by an automatic snapshot of your working tree, listed under **AI checkpoints** in the Source Control panel with a Revert button. This turns the scariest part of an agentic terminal — "it just rewrote a file and I don't know what it changed" — into a reversible operation, using nothing but local git. `git stash create` is the primitive: it builds a commit object for the current state **without touching the index, the working tree, or the stash list**, which is what makes it safe to run on every agent edit (a `stash push` would mutate your tree; a real commit would pollute your history). The object is anchored under `refs/nexis/checkpoints/`, a namespace that never appears in `git log`, `git branch`, or a default push. **A checkpoint never blocks an edit** — no repo, no git, a permissions problem, all resolve to "proceed without a checkpoint", because the snapshot is a safety net and not a precondition; a clean tree returns no checkpoint at all rather than burying the useful entries in empty ones.
  Two findings from testing this against real repositories are worth recording. **Revert uses `git restore --source`, not `git stash apply`** — the stash route was implemented first and is simply wrong here: `stash apply` refuses when the working tree has conflicting local changes, and the agent's edit *is* exactly such a change, so it failed in precisely the situation the button exists for. (`git restore` needs git 2.23, already Nexis's minimum.) And because overwriting is destructive to anything changed since the snapshot, **the revert takes its own checkpoint first**, so a mis-click costs one more click instead of your work — the undo is undoable. Separately, the label had to move into the ref *name*: `update-ref -m` writes a reflog git doesn't keep for refs outside `refs/heads|remotes|notes`, and the commit's own subject is git's "WIP on <branch>" boilerplate, which would have told you nothing about what the agent was doing. Known limitation, inherited knowingly: `stash create` snapshots **tracked files only**, so a brand-new file the agent creates isn't in the checkpoint — the dangerous, hard-to-undo case is an agent overwriting code you already had, and deleting a file it just created is trivial by comparison. Restore and delete both validate the ref against the checkpoint namespace before running, so a crafted value can't `restore` an arbitrary commit over your tree or delete `refs/heads/main`.
- **Missing external tools now say so, with the command to install them.** Nexis shells out to language servers, formatters, and git rather than bundling them — that is what keeps the binary under 10 MB — but the failure mode of that choice was silence: a missing `rust-analyzer` meant completions simply never appeared, with nothing anywhere explaining why (`client.ts` literally read *"Server not installed or failed to start — silently degrade"*). A status-bar notice now names each tool Nexis wanted but couldn't find, what stopped working *in user terms* ("Completions, diagnostics, and inlay hints in Rust files"), and a copyable per-platform install command. Covers every language server in `LANGUAGE_SERVERS` plus git, and a test asserts that coverage against the server table — adding a server without an install hint fails the build rather than quietly reintroducing the silent no-op. That test earned itself immediately: it caught four servers (`lua`, `clangd`, `csharp-ls`, and a binary-name mismatch) missing from the first draft of the matrix. Design notes: tools are reported **lazily, on first failed use**, not by probing PATH at startup — probing would spawn a dozen processes every launch to answer a question most users never ask, and would announce that `gopls` is missing to someone who has never opened a Go file. A tool that starts working mid-session (you installed it) clears its own notice without a restart, repeated failures don't stack a duplicate entry, and each notice can be dismissed for the session. Git is detected by matching the Rust side's `GitError::NotInstalled` message, with **tests on both sides of the IPC boundary pinned to the same wording** — git errors cross as plain strings, so that phrase is the only thing linking them, and a Rust-side test now fails if it changes without the frontend matcher.
- **The file explorer now updates from a native filesystem watcher instead of a 3-second poll.** A file your build just produced appears immediately rather than up to three seconds later, and an idle explorer stops doing a full directory re-list every tick regardless of whether anything changed. Backed by the `notify` crate (`modules/fswatch.rs`), which adds ~96 KiB to the release binary. The design point worth knowing: **establishing a recursive watch can legitimately fail** — Linux's `fs.inotify.max_user_watches` is commonly 8192 and a single `node_modules` can exhaust it — so `fs_watch_start` reports whether the watch actually took, and the explorer *keeps the 3 s poll as a fallback* when it didn't. Treating the watcher as guaranteed would have presented as "the file tree silently stopped updating", and would have done so on exactly the largest projects. Events are debounced 250 ms **in Rust**, because a single `git checkout` or `cargo build` emits thousands in a burst and forwarding each across IPC would flood the webview with work it would only coalesce anyway; noisy directories (`.git`, `node_modules`, `target`, `dist`, `.venv`, …) are filtered out on the event, since a recursive watch offers no per-subtree exclusion and an unfiltered background build would refresh the tree continuously for changes the user cannot see. Access/read events are ignored outright — otherwise an editor or a `grep` would keep the tree churning. The emitted payload is a signal, not a diff: the explorer re-lists the visible tree exactly as the poll did, because path-level patching of a lazily-expanded tree is a much larger change and the re-list was already cheap enough to run unconditionally every 3 s. A watcher error still triggers a refresh rather than risking a stale tree.
- **Custom AI tools — write your own agent tool in TypeScript, scaffolded by one command.** `pnpm tool:new <name>` generates a working tool plus a passing test, registers it in a custom-tools plugin, and wires that plugin into the app; `--auto` marks a read-only tool as no-confirmation. Plugins gain `api.registerTool()`, and contributed tools are merged into the agent's tool set alongside the built-ins. The guide is [`docs/architecture/custom-ai-tools.md`](docs/architecture/custom-ai-tools.md). Because a contributed tool runs inside the agent loop with the same reach as a built-in, admission is deliberately strict and lives in one pure function rather than at each registration site: **a contribution can never shadow a built-in name** — re-binding `read_file` would swap a guarded primitive for an unguarded one, and the built-ins are additionally spread *after* plugin tools so that even a built-in added without updating the reserved list fails safe; **names are validated, not trusted**, because the name crosses into the provider's function-calling schema where an invalid one fails the entire request rather than just that tool; **first registration wins** on a duplicate; and a tool with no description is refused outright, since the model cannot use an unlabelled tool. Every rejection is logged with the offending tool's id and skipped — never thrown — so one malformed plugin cannot disarm the others or break a turn, and a tool that throws at runtime is converted into an error *result* the model can read and recover from. **Contributed tools require user approval by default**, using the same confirmation card as `write_file` and `bash_run`; `approval: "auto"` is opt-in and documented as read-only-only. Authoring is supported by a local harness (`runTool` / `createTestToolContext`) that runs a tool exactly as the agent loop would — including admission and schema validation — so a tool that would be silently rejected in the app fails in the author's own test instead, and it returns `{ ok: false, error }` rather than throwing so failure paths are as easy to assert as successes. A sync test pins the reserved-name list against what `buildTools()` actually registers; it caught three wrong names the first time it ran, which is precisely the hole a plugin could otherwise have occupied.
- **The exit-status gutter is now a per-command block affordance — hover to identify, click to copy.** Every finished command already painted a green/red bar in the gutter; that bar now also knows *which* command it belongs to. Hovering names the command and its exit status, and clicking copies the command to the clipboard — so re-running something from twenty commands back no longer means selecting text out of the scrollback by hand. This is the next slice of the roadmap's block-mode item after prompt-block navigation, and like that one it is pure frontend over OSC 133 markers the shell profile already emits. Details worth knowing: **only the command text is retained per block, never its output** — a block index spans the whole scrollback (up to 2000 markers), and holding each command's output would put tens of megabytes behind a feature whose job is to copy a one-line command; output stays reachable through ordinary selection. The command is captured at `OSC 133 D` time rather than read lazily on click, because by the time anyone clicks, those buffer rows may have scrolled away or been overwritten — reading late would hand back the wrong text exactly when the scrollback is long enough for the feature to matter. The bar's *hit* area widens to 6px while the painted bar stays 2px, since a 2px click target is not realistically clickable; handlers are assigned as element properties rather than via `addEventListener`, because xterm re-invokes `onRender` on every repaint and listeners would otherwise stack (the same rule the "✦ Explain" chip follows, now covered by a test). A block with no captured command — no `OSC 133 B`, so nothing was typed — stays inert rather than offering an empty copy. The command-boundary logic is now shared with the failed-command capture instead of duplicated, so the two can't drift into disagreeing about where a command ends and its output begins.
- **Inline images in the terminal — Sixel and the iTerm2 inline-image protocol.** `icat`, `chafa`, `img2sixel`, a `curl`'d PNG, and — the case that motivated this — a `nexis-ml` training-run plot now render directly in the scrollback instead of printing escape-sequence garbage or nothing at all. This is what Kitty, WezTerm, and iTerm2 are reached for and Nexis previously couldn't do. It needed no renderer rewrite: `@xterm/addon-image` is a drop-in xterm.js addon, so it slots into the existing renderer pool beside the fit/search/serialize/web-links addons and costs ~55 kB (17 kB gzipped) in the already-split `xterm` chunk, not the main bundle. Two decisions are load-bearing and both are tripwired. **The per-terminal image budget is capped at 16 MB, down from the addon's 128 MB default** — that default is per-*terminal*, and this pool keeps up to `POOL_MAX_SIZE` (5) live terminals, so accepting it would have authorized roughly 640 MB of decoded RGBA across a full pool; storage is FIFO, so exceeding the cap evicts the oldest images rather than rejecting new ones. **Recycled slots explicitly reset the image addon**, because renderer slots are pooled and reused across unrelated sessions while decoded images live in the addon's own storage rather than the xterm buffer that `term.reset()` clears — without it a fresh terminal could surface the previous session's images and pin their memory indefinitely. Also worth knowing: the addon's window size reports (`CSI 14/16/18 t`) are left enabled, since they are how image-emitting tools ask for the cell and window pixel size and scale correctly; the replies ride the same `onData` → `pty_write` writer path as keystrokes, so they keep the existing input-ordering guarantee instead of racing ahead of typed input. Kitty's own graphics protocol is a separate specification and is not part of this.
- **Plugins can now contribute sidebar panels (expansion packs V2).** The plugin registry has been able to *store* a `PanelContribution` since V1, but nothing ever rendered one — the type had no icon, group, or pack, and the rail only knew its own hardwired list. Both gaps are closed: `PanelContribution` gains optional `icon`, `group`, `pack`, and `order`, the rail renders contributed panels beside the built-ins, and a contributed panel is gated by its declared expansion pack exactly like a built-in view — same "This panel is part of the X pack — Enable?" placeholder. The design choice worth recording is that a contributed panel's view id is namespaced (`plugin:<contribution-id>`) rather than widening the built-in `SidebarViewId` union to `string`: the union stays closed and exhaustively checkable, and a plugin registering `id: "explorer"` produces `plugin:explorer` — a distinct view that cannot shadow or displace the real file explorer. Two consequences fall out of that and are handled deliberately. Sidebar state is restored from `localStorage` **before** any plugin registers, so validation of a persisted plugin view has to work without consulting the registry (the prefix shape alone is enough), and an unresolved contribution renders a neutral "isn't available" state rather than redirecting to the explorer — a redirect would silently discard the user's selected view on every launch, and would do it more often on slower machines, presenting as a preference that refuses to stick. Contributed panels with no `group` land in Advanced, and `order` (tie-broken by title) keeps the rail stable given that plugins register in nondeterministic order. Resolution logic is pure and covered by 17 unit tests. **No built-in panel has been migrated yet** — that stays incremental, because moving one changes its persisted view id and must ship with a one-time id remap for saved sidebar state and pinned-rail entries in the same change. Full design record in `docs/vault/decisions/expansion-packs.md`.
- **System Monitor — a btop-style resource analyzer in the sidebar.** A new Dev Tools panel showing per-core CPU, memory and swap, per-disk capacity and I/O, per-interface network throughput, load average, uptime, and a sortable, filterable process table with kill actions. The charts are drawn in the btop idiom — braille sparklines rather than a dashboard of gauges — which is not a stylistic accident: a braille cell packs a 2×4 dot matrix into one character, so a chart is a *string* that inherits the active theme's colors and the app's monospace metrics for free, with no canvas context, no per-frame allocation, and nothing to resize. Sampling lives in Rust (`modules/sysmon.rs`) behind a polling command using `sysinfo`, deliberately feature-minimal (`system`, `disk`, `network` only — the default set pulls thermal sensors, passwd/SAM lookups, and rayon, none of which the panel reads); the Windows binary grows ~168 KiB and stays inside the 10 MB budget, which was checked before the dependency was committed to rather than after. Details worth knowing: **CPU, disk, and network figures are all deltas between two refreshes**, so the first sample after opening the panel has nothing to diff against and its rate charts start one tick behind the absolute readings — that is why memory and disk capacity appear instantly but the CPU line does not. Rates are normalized to per-second **in Rust**, because only the sampler knows the true elapsed interval, which drifts from the nominal poll period exactly when the machine is loaded and the reading matters most; dividing by an assumed interval would make every chart lie under load. The process table is sorted *and then* truncated in Rust (cap 250 rows), so the rows that survive are always the ones the chosen sort asked for, and the header honestly reports "N of M" rather than implying the machine only has 250 processes. Polling is self-scheduling rather than `setInterval` — on a loaded machine a process refresh can outlast the interval, and overlapping samples would pile onto the same sampler mutex, each making the next slower. Killing a row sends `SIGTERM` so the process can clean up; shift-click escalates to `SIGKILL`, and the target pid is re-resolved immediately before signalling so a stale table can't send a signal to a pid the OS has since recycled. The panel is lazy-loaded, so it only polls while it is the selected view. It sits **beside** the existing Activity panel rather than absorbing it — Activity tracks Nexis's own agent-spawned background processes, which is a different question with a different data source. Requires the Dev Tools expansion pack.
- **Quick terminal — a drop-down shell summoned from any app.** Off by default; turn it on in Settings → General and `Ctrl+Shift+`` ` (`⌃⇧`` ` — `⌘⇧`` ` on macOS) drops a borderless terminal from the top of whichever screen you're on, from inside any application. Press it again, or click away, to dismiss. This is the one feature people most often keep a second terminal app around for (iTerm2's Hotkey Window, Ghostty's Quick Terminal), and it needed no new backend surface: the drop-down is an ordinary Nexis window loading `/?quick=1`, rendered in the existing zen mode, running the same PTY and session stack as every other window. Settings expose the height (20–90% of the screen, default 40%) and whether it hides on focus loss — turn that off to keep it pinned while you work in another app. Details worth knowing: the window is hidden rather than destroyed on dismiss, so your shell and scrollback survive between summons and only the first press pays a cold start; it re-positions onto the active monitor on every summon, so it follows you across displays instead of appearing on the screen you opened it on; and the accelerator is registered only by the main window, since a global shortcut is process-wide and would otherwise fire once per open window. The default chord deliberately includes `Shift` so the very common plain `Ctrl+`` ` that editors and terminals bind for their own panels is left alone. Hotkey registration failures — most often another app already owning the accelerator — are logged and left non-fatal rather than taking down startup, so the symptom is an inert hotkey you can change, not a broken app. Adds `tauri-plugin-global-shortcut`; the Windows binary stays inside the 10 MB budget (the X11 backend it pulls in is Linux-only).
- **Prompt-block navigation — jump the scrollback command by command.** `Ctrl+Shift+↑` / `Ctrl+Shift+↓` (`⌘⇧↑` / `⌘⇧↓` on macOS, matching iTerm2's previous/next mark) scroll the terminal to the previous or next command prompt instead of by line or page. Finding where the last build actually started no longer means dragging the scrollbar and reading for a prompt. This is the first slice of the roadmap's block-mode terminal item and it needed no new machinery: the OSC 133 `A` markers that already drive the exit-status gutter are now also kept as a per-terminal navigation index, so the feature is pure frontend over markers the shell profile has been emitting all along. Consequences worth knowing: it requires shell integration (without OSC 133 markers there is nothing to jump between, and the keypress is a silent no-op), and it is a no-op at either end of the scrollback rather than clamping, so holding the key at the oldest prompt doesn't jitter the viewport. The chord is swallowed either way so it can never leak to the PTY as a stray escape sequence, and `Shift` is required precisely so the plain `Ctrl+↑`/`Ctrl+↓` some shells bind still reaches the shell untouched. Markers are pruned lazily on keypress (not on every prompt the shell draws) and capped at 2000, so a large `scrollback` setting can't grow the index without bound.

### Fixed
- **The window no longer reopens larger than the screen it lands on (mixed-DPI multi-monitor).** `tauri-plugin-window-state` stores window size in **device pixels** and records nothing about which monitor or scale factor produced them; on restore it validates the saved *position* against the connected monitors but never the *size*. On a mixed-DPI layout — reported on KDE Wayland with a 4K panel at scale 2 beside a 1080p panel at scale 1 — a size captured on the HiDPI output is replayed verbatim onto the 1x output, where the same device-pixel count is physically twice as large: the window opens wider and taller than the display with its bottom edge, status bar included, below the desktop and no way to drag it back. The same layout also produced a saved position of `(0, 0)`, which is on *neither* monitor (the outputs start at `x=3840` and `y=410`), leaving placement entirely to the compositor. A new pre-flight pass (`src-tauri/src/modules/winstate.rs`) reads the state file and repairs it **before any window is created**, so the plugin restores values that already fit; each saved window is matched to a monitor by containment, then by greatest overlap, then — only if it is fully off-screen — re-homed onto the largest display, and its size and position are clamped into that monitor's work area. Matching by overlap rather than always taking the largest monitor is deliberate: a window legitimately sized for a 4K display must not be shrunk to a 1080p one. Maximized and fullscreen windows are skipped (they are legitimately screen-sized and the plugin restores those flags separately), a healthy state file is never rewritten, and every failure path — missing, unreadable, or malformed file — is a silent no-op that falls back to the configured defaults.
  Repairing the file rather than resizing the live window is the whole trick, and the alternative was tried first and abandoned: post-hoc correction cannot work reliably, because an unmapped window has no monitor under Wayland (`current_monitor` *and* `primary_monitor` both return `None`, so a clamp in `setup()` silently does nothing), and once it is mapped its scale factor is stale and unstable *during* the corrective resize — the window's factor and the target monitor's disagree until GTK reconciles them after the move, so a `set_size` gets converted by the wrong factor and lands at half the intended size. The geometry logic is a pure function with unit tests covering the reported layout, the off-screen case, the single-monitor case, and a regression guard that a large window is not shrunk to a smaller sibling monitor.

### Security
- **`quick-xml` upgraded 0.39.4 → 0.41.0 — closes two high-severity DoS advisories (RUSTSEC-2026-0194/0195).** The quadratic-time duplicate-attribute check and the unbounded `xmlns` namespace-declaration allocation both enable memory/CPU-exhaustion denial of service on a malicious XML document. `quick-xml` is a transitive dependency (`tauri-utils → plist → quick-xml`), and the fix needed no Tauri bump: `plist` moved 1.9.0 → 1.10.0 — permitted by Tauri's `plist = "^1"` — which requires `quick-xml ^0.41`, so a plain `cargo update -p plist` pulled the fixed version. Practical exposure here was low (the crate parses our own bundler/config property-list XML, not attacker-controlled runtime input), but `cargo audit` fails hard on any vulnerability, so this keeps the CI supply-chain gate green. The two now-obsolete advisory ignores were removed from `src-tauri/deny.toml` (they'd otherwise silently suppress a future regression); `cargo deny check` stays clean.

### Fixed
- **Windows clippy gate no longer fails on `child_pid` dead code.** The `Session.child_pid` field is read only by the Linux-only `/proc/<pid>/cwd` cwd fallback (`pty_cwd`, `#[cfg(target_os = "linux")]`) but is set on every platform, so on Windows/macOS it counted as dead code — and the CI clippy job (which runs on `windows-latest` specifically to lint the Windows `cfg` paths) promoted it to a hard error under `-D warnings`. Gated an `allow(dead_code)` to non-Linux targets, so the lint still enforces that the Linux fallback actually reads the field. Latent since the fallback shipped; it only surfaced once the backlog of unpushed commits reached CI.

## [1.21.0] — 2026-07-18

A security-and-AI release. The headline security work: LAN sharing is no longer open to anyone who can reach the port — every share session mints a token checked on all routes, with a bind-interface picker (all / LAN-only / localhost) and a persistent "Sharing on" status-bar pill so it can't run unnoticed; secret redaction now scrubs the share stream and saved recordings; the webview's `connect-src` is pinned to the updater endpoint instead of blanket HTTPS; every agent shell command is written to an append-only audit log; and the nexis-ml engine download is a consented, SHA-256-pinned install flow. On the AI side, three terminal-native affordances land: **AI command search** (describe a command in plain English, get it inserted at the prompt — never auto-run), a **"✦ Explain" chip** on any failed command, and a **scoped auto-approve** policy that runs a strict read-only allowlist without prompting while everything else still asks. Reliability got a PTY stall watchdog, editor autosave with crash recovery, scrollback that survives a relaunch (persistent sessions, Milestone A), and shell-integration cwd fallback; performance got the minimap rewritten on canvas, parked-slot WebGL reaping, and the `motion` library replaced by plain CSS. Rounding it out: the sidebar's feature surface is now core + opt-in expansion packs, plus zen mode, MRU Ctrl+Tab, OSC 52 clipboard, a diagnostics-bundle export, and a batch of settings wins.

### Security
- **LAN sharing now requires the link, not just the network — plus a bind-interface picker and a persistent "Sharing on" pill.** The share server previously served the conversation or terminal to *anyone* who could reach the port, always on every interface (`0.0.0.0`). Four changes close this out:
  - **Tokenized links.** Every share session gets a fresh 128-bit token (webview CSPRNG); every route — the page, the `/stream` SSE feed, and the `/ws` WebSocket — rejects requests without `?k=<token>` with a 403, before revealing anything (not even whether it's a conversation or a terminal). The compare is constant-time Rust-side, and Rust re-validates the token shape (≥16 chars, alphanumeric-only) so a frontend bug can't silently start an unauthenticated server. Live pages embed the token in their WS/SSE URLs, so viewers just open the link. Loopback tests cover missing/wrong/prefix tokens on all three routes.
  - **Bind-interface picker.** "Visible on" in the Share panel: **All networks** (0.0.0.0, the old behavior, still the default), **LAN only** (binds just the primary LAN interface — not exposed on VPN/Docker/other networks), or **This device only** (127.0.0.1). The LAN IP comes from a new `http_share_lan_ip` command (UDP route-lookup trick — no packet leaves the machine), which also replaces the URL display's literal `192.168.x.x` placeholder: the panel now shows — and the copy button copies — the real, complete, tokenized URL.
  - **Sharing outlives the panel, and the status bar says so.** Share state moved from panel-local React state to a global store: switching sidebar views no longer silently kills the server (or the live push loop, which now runs at module level). In exchange, a red pulsing **"Sharing on" pill** sits in the status bar the whole time the server runs — whatever panel or pack is active — with the URL and scope in its tooltip; clicking it opens the Share panel to stop or manage. You can share, work elsewhere, and never *unknowingly* keep broadcasting.
  - **The initial page is now redacted too.** `redactSensitive()` previously covered live updates and the stream but not the very first HTML handed to `http_share_start` — the first thing a viewer downloads. It now takes the same pass, and the redaction tripwire in `pitfall-guards.test.ts` grew a third assertion so this path stays covered.

  This is the read-only-auth half of the roadmap's multiplayer-terminal story; remote *input* still needs its own consent model and stays out.
- **AI command audit log.** Every shell command the agent runs — and every one the safety layer blocks — is appended as a JSON line to `{data}/nexis/ai-command-audit.log`: timestamp (stamped Rust-side), command, cwd, exit code/timeout for `bash_run`, spawn handle for `bash_background`, kills, and block reasons. The file is append-only from the app's side (never rewritten or truncated; entries themselves cap at 8 KiB), auditing is fire-and-forget so it can never break or slow a tool call, and **Settings → General → Debug → "AI command audit log" → Reveal** opens its location. The roadmap's companion idea — "require approval for commands matching *pattern*" — is deliberately not built: both agent shell tools already require approval unconditionally, so a pattern list would only matter if an auto-approve mode ever ships; noted on the roadmap for that day.
- **Secret redaction now covers the LAN share stream and saved recordings.** The `redactSensitive()` scrubber (OpenAI/Anthropic/AWS/GitHub/Google/Slack/Stripe key shapes, JWTs, `Bearer` headers, `*_PASSWORD/SECRET/TOKEN=` assignments) previously guarded only the AI-context path; it now also runs on everything the LAN share server emits (`http_share_update` HTML and the live SSE stream) and on every output event written into a `.cast` recording — the two surfaces that leave the machine, as remote viewers and bug-report attachments. A new tripwire in `pitfall-guards.test.ts` fails the build if either surface stops routing through the scrubber, and the scrubber itself gained a 20-case test suite (every pattern, false-positive checks, idempotence, and the documented fail-closed over-redaction of `PASSWORD_*`-named config values).

- **Webview `connect-src` no longer allows arbitrary HTTPS hosts.** The CSP's blanket `https:` in `connect-src` is now pinned to `https://api.github.com` (the update check, the webview's only legitimate remote fetch). Everything else already goes through the Rust proxy with its SSRF guards — AI providers via `ai_http_request/stream`, preview-port probes to `localhost` only — so any future or compromised frontend code can no longer silently exfiltrate via a direct `fetch` to an attacker host. Deliberately unchanged: `frame-src http: https:` stays, because the preview address bar intentionally loads user-typed sites in a sandboxed cross-origin iframe (no Tauri IPC access); tightening it is a product decision, not a hardening fix. Remote images in markdown remain blocked by the existing `img-src` (no `http:`/`https:`), which is the lock-down the hardening backlog asked for.

### Changed
- **Minimap rewritten as a canvas driven by a CodeMirror `updateListener` — the 200 ms poll is gone.** The minimap used to render one `<div>` per document line and refresh on an interval; on a 10k-line file that meant 10k DOM nodes diffed on a timer even when nothing changed. It's now a single `<canvas>` repainted (one `fillRect` per non-empty line, rAF-coalesced, DPR-aware) only when the document or geometry actually changes, delivered through a `minimapUpdateExtension` included in the editor's identity-stable extensions array. Scroll still only moves the viewport-indicator div — no repaint — and strip colors resolve from the container's computed foreground, so themes keep working with zero config. Idle cost is now exactly zero. (The cheap memoization half of this shipped in 1.20.6; this completes the rewrite the hardening backlog tracked.)

### Added
- **AI command search — natural language → command, in the terminal.** **Ctrl/Cmd+Shift+I** (or "AI command search" in the palette) floats a compact bar over the active terminal pane: describe what you want in plain English, Enter asks the configured provider (any BYOK/local model — the same `buildConfiguredLanguageModel` path as chat, with shell, OS, and the pane's current cwd in the prompt), and back comes one runnable command plus a one-line explanation. A second Enter — or the button — **inserts the command at the shell prompt; nothing is ever executed from the bar**, so the user's own Enter at the prompt is the confirmation step (the roadmap's "confirm before it goes to the shell", done structurally instead of with a dialog). That insert-only contract is enforced in the parser, not the UI: suggestions are rejected outright if multi-line or containing any control character (a stray `\r` in inserted text would execute without consent), multi-line fenced scripts are refused rather than truncated to a first line that would do something else, and over-long output is dropped. Commands the destructive-command heuristic flags get an inline ⚠ caution (not a block — nothing runs without the user); the model is prompted to decline destructive/ambiguous requests with an explanation instead of guessing, and a decline renders as prose, not an insertable command. Parser tolerates bare JSON, fenced JSON, JSON embedded in prose, single-command fences, and bare single-line replies (21 unit tests, including the control-character and truncation guarantees). No provider configured → the error state links to Settings → Models. The shortcut dispatches a window event (`nexis:terminal-ai-command`) answered by the visible focused pane — same decoupling as selections and the Explain chip.
- **Scoped auto-approve for read-only agent shell commands.** The tool-approval policies (Settings → Agents) grow a fourth option, offered only for `bash_run`: **"Auto-approve read-only"** (`auto-safe`). Eligible commands run without the approval pause — the chat shows a compact "Auto-approved · read-only" line with the command — and *everything else falls back to today's prompt*, unlike the pre-existing blanket "Auto-approve" (Warp's Yolo-mode shape, which remains available but now has a sane middle ground). Eligibility (`checkAutoApprove` in `ai/lib/security.ts`) is an allowlist, not a denylist: printable ASCII only (rejects homoglyph/bidi tricks wholesale), zero shell machinery (no pipes, redirects, substitutions, quoting, globs, `;`/`&` — nor `%`, because the Windows agent shell can be cmd.exe where `%VAR%` expands past any literal check), a curated set of read-only binaries (`ls`, `cat`, `head`, `tail`, `wc`, `stat`, `file`, `du`, `df`, `pwd`, `which`, `echo`, …), and git confined to read-only subcommands with the `-c`/`--git-dir` global-flag tricks structurally impossible (the token after `git` must itself be an allowlisted subcommand) and `--output*`/`--ext-diff`/`--textconv` denied. Every path-shaped argument — including `--flag=value` values and each segment of git's `rev:path` syntax, so `git show HEAD:.env` is as blocked as `cat .env` — must pass the same `checkReadable` secret-file guards the auto-approving fs read tools use; the mode can read nothing they couldn't already. Deliberately excluded: `bash_background` (a "read-only" daemon is a contradiction), recursive readers like `rg`/`grep`/`find` (they surface protected content from innocent starting points), `env`/`printenv` (the environment carries secrets), and user-editable patterns (an allowlist you can append `rm *` to isn't an allowlist — revisit only if real usage demands it). The audit log now annotates every `run`/`background` entry with how the gate was passed (`approval: "user" | "auto" | "auto-safe"`), completing the "pattern rules only alongside an auto-approve mode" plan from the audit-log release. Covered by ~100 unit cases plus fuzz properties (never throws; everything eligible also passes the destructive-command check; no eligible command names a path `checkReadable` refuses).
- **PTY input-ordering audit + tripwires — device-query replies verified unable to interleave with keystrokes.** The hardening backlog asked whether frontend-generated device-query replies (DA/DSR/CPR cursor reports, which xterm.js answers on the app's behalf) could interleave with user keystrokes on the PTY — the exact ordering-bug class upstream terax hit in July 2026 (their #1004). Verified immune by construction: xterm emits replies through the same `onData` stream as keystrokes, every write funnels through the single `pty_write` invoke in `pty-bridge.ts`, `pty_write` is a *sync* command (Tauri executes those on the main thread in IPC arrival order — async commands run concurrently and could reorder rapid writes), and it only enqueues to the per-session `nexis-pty-writer` FIFO channel that serializes bytes onto the PTY. Since every link is load-bearing and none would fail a test if quietly broken, the chain is now tripwired both sides: `pty_write_stays_sync_and_enqueue_only` in `src-tauri/tests/pitfall_invariants.rs` (stays sync, enqueues to `write_tx`, no `spawn_blocking`/`thread::spawn`/direct `write_all`) and a `pty_write`-confinement guard in `src/lib/pitfall-guards.test.ts` (no second invoke site, mirroring the existing `pty_open` guard).
- **"✦ Explain" on a failed command — one click sends the failure to the AI chat.** Commands that exit nonzero (already detected via the OSC 133 shell-integration markers that drive the red exit gutter) now grow a small right-anchored "✦ Explain" chip on their prompt line; clicking it attaches the command line, its output, the exit code, and the cwd it ran in as terminal context and auto-submits a fix-suggestion prompt to the AI chat (Warp's flagship AI affordance, built entirely on data Nexis already had). Capture happens at command-exit time from the buffer between the B/C markers and the cursor: output is tail-biased and capped (200 lines / 16 KB, `[… earlier output truncated …]` when cut, errors live at the end), cwd is read *before* the shell's post-command OSC 7 so a failed `cd` can't skew it, and the chip persists down the scrollback like the gutter bar so older failures stay clickable until they scroll out. Deliberate non-triggers: exit 130 (Ctrl+C is a cancel, not a failure), a bare Enter re-emitting the stale `$?` (zsh/bash precmd does this — the chip requires evidence a command actually ran), and shells without integration (no markers, no chip — same constraint as the gutter). On PowerShell, whose profile emits no `C` marker, the capture degrades gracefully: the input line is the command, everything below is treated as output. No AI provider configured → the click opens Settings → Models, matching every other AI entry point. Toggle: **Settings → General → "Explain failed commands with AI"** (`terminalExplainFailures`, default on, `writePref()`-synced). The terminal side only dispatches a `nexis:ai-explain-failure` window event — the same decoupling as selections — bridged into the composer in `App.tsx`; capture, guards, truncation, wrapped-row joining, and chip lifecycle are covered by nine new osc-handler tests.
- **Diagnostics bundle export.** **Settings → General → Debug → "Diagnostics bundle" → Export** writes `~/nexis-diagnostics-<unix>.zip` containing: app/OS versions, the settings JSON (passed through `redactSensitive()` frontend-side — the command never reads the raw store), the 5 newest log files and crash reports (last 512 KiB of each, tail-snapped to a UTF-8 boundary), and the newest terminal recording (≤4 MiB, already redacted at save). Everything stays local — the user attaches the file to a bug report themselves. The zip is produced by a ~100-line store-only writer instead of a zip crate: logs and JSON are small, and the <10 MB binary budget outweighs compressed bundles. Structure, CRC-32, and the UTF-8 tail-snap are unit-tested.
- **PTY thread watchdog — a stalled terminal now says so.** Pitfall #8's failure shape (an internal reader/flusher thread dies while the shell keeps running) previously left the terminal permanently, silently blank. Each PTY I/O thread now carries a drop-guard sentinel that flips on any exit — panic included — and a single global `nexis-pty-watchdog` thread scans registered sessions every 5 s: a thread dead past a 5 s grace period without the session's normal exit handoff pushes a red `[nexis: terminal stalled …]` notice into the terminal, delivered straight down the session's IPC channel, which still works with both PTY threads dead. Deliberately *not* surfaced as a fake shell-exit event: the frontend auto-respawns (or closes the pane) on exit, which would silently kill a child that may still be running the user's work — a stalled terminal stays open with an explanation and the user decides. The grace window absorbs normal teardown (reader EOF precedes the waiter's exit record by design); the decision core is a pure function with unit tests covering the transient-vs-stall distinction and the panic-unwind sentinel.
- **Editor autosave + crash recovery.** While a buffer is dirty, the editor snapshots it to `~/.cache/nexis/editor-autosave/` two seconds after the last keystroke (atomic tmp+rename; skipped above 4 MiB, matching the large-file tier), and deletes the snapshot on save — so a crash or force-kill never loses more than a couple of seconds of typing. On the next open of the same file (tab restore reopens editor tabs, so this happens automatically after a crash), a snapshot that still differs from disk raises a banner — **Restore** adopts it as the dirty buffer (the snapshot stays until an actual save, in case this session dies too), **Discard** deletes it; one matching disk is silently dropped as a completed-save leftover. Files are keyed by an FNV-1a hash of the path with the original path stored inside the record, so a hash collision can never surface another file's content — and the hash is hand-pinned rather than `DefaultHasher`, whose output may change between Rust releases and would orphan recoveries across an app upgrade. Recoveries older than 7 days are swept once per launch. New IPC family `editor_autosave_write/read/delete/sweep` (async via `heavy()`), unit-tested including the collision guard and the sweep.
- **Opt-in FPS meter in the status bar.** **Settings → General → Debug → "FPS meter"** (default off) shows a Zed-style frame-rate pill: frames over the last rolling second, turning red below 30 fps, with average and worst frame time over a 5 s window in the tooltip. Measured via `requestAnimationFrame` — rAF ticks every vsync while the main thread keeps up, so missed ticks are exactly main-thread jank (long tasks, layout storms); it deliberately does *not* claim to see GPU/compositor stalls, and the tooltip says so. Hidden-window gaps (rAF suspends) are filtered out so resume doesn't register as a fake jank spike, and the loop itself stays allocation-light with display updates throttled to 2/s so the meter doesn't distort what it measures. Zero cost while off — the pill isn't mounted and no rAF loop runs.
- **Large-file editor mode — heavy tooling backs off above 2 MiB.** Opening a file larger than `LARGE_FILE_BYTES` (2 MiB) still loads the buffer, but the pane starts with the language server, syntax linting, code folding, the minimap, and AI inline completion disabled, under a banner naming the size and offering **Enable anyway** (remembered per path for the session). Everything reactivates in place on click — LSP attaches, lint reconfigures via a compartment (the extensions array keeps its identity, per the editor's stable-identity invariant), the fold gutter and minimap return. Distinct from the existing hard `fs_read_file` cap, which refuses to open the file at all; this tier keeps huge logs and generated files *editable* without the tooling churn that made them crawl. (Upstream terax shipped the same tiering in 0.8.5, confirming the demand.)
- **Persistent terminal sessions, Milestone A — scrollback survives a relaunch.** On window close, each non-private terminal tab's buffer is serialized (the renderer pool's `SerializeAddon` path for on-screen tabs; parked tabs reuse their parked snapshot plus any dormant output) and written atomically (tmp + rename) to `~/.cache/nexis/session-snapshots/<id>.snap`, keyed by a stable per-tab snapshot id carried in the persisted tab state. On relaunch, a restored tab replays that scrollback above a dim `── session restored · previous shell ended ──` divider *before* the fresh shell spawns in the saved cwd — the load is chained ahead of the slot bind and PTY open, so the first prompt can never race the replay. Toggle: **Settings → General → Startup → "Restore scrollback on relaunch"** (default on; it only applies while "Restore tabs on launch" is on). Guardrails: private tabs never write snapshots; closing a tab (or resetting the workspace) deletes its file; an exit-time gc removes files for tabs that no longer exist — or all files when either setting is off; snapshots are trimmed to 4M chars frontend-side and hard-capped at 12 MiB in Rust (`session_snapshot_save/load/delete/gc`, all `heavy()`-async, ids charset-validated against path traversal); the close handler waits at most 1.5 s so a hung IPC can never block exit. Known limits, inherited from tab persistence: only the active pane of a split tab is snapshotted, and alt-screen (TUI) dormant output is skipped — the same reason slot rebinds discard it. Live processes still end with the app; that's Milestone B (the PTY broker).
- **Shell-integration resilience — cwd tracking no longer silently dies when the integration isn't sourced.** Nexis's cwd tracking (tab labels, "open new tab here", terminal suggestions, the git panel's repo resolution) depends on the shell profile emitting OSC 7, which never arrives under a custom shell or rc files that skip the injected integration. Each session now tracks whether *any* integration marker (OSC 133, or an OSC 7 accepted outside a running command) has arrived; if none has ~5 s after the shell starts, Nexis logs the degradation once and falls back to asking the OS for the shell process's real cwd (`pty_cwd`, a `/proc/<pid>/cwd` readlink — Linux only; other platforms keep the old behavior) on a low-rate 3 s poll. The poll self-cancels the moment a real marker arrives (late-sourced integration wins), and a rejected in-command OSC 7 deliberately does *not* count as "integration present" — untrusted command output must not be able to switch the fallback off. Timers are cleared on dispose/respawn; covered by new osc-handler tests.
- **Opt-in memory self-report in the status bar.** **Settings → General → Debug → "Memory self-report"** (default off) adds a compact status-bar pill polling every 2 s: renderer-pool slot count and live WebGL contexts (so the 1.20.7 slot-reaping win stays observably true), buffered scrollback lines across both xterm buffers per slot (arithmetic over line counts — never serializes buffer contents), dormant-tab output bytes and parked snapshot sizes, in-flight recording size, and the approximate serialized size of AI chat histories (~4 bytes/token) — hover for the full breakdown. Zero cost while off: the pill isn't mounted, no polling runs, and the AI-history tracker stores only array references (`approxHistoryBytes()` serializes lazily, with the pitfall-#11 defensive catch). New stat probes: `poolMemoryStats()` (rendererPool), `sessionMemoryStats()` (useTerminalSession), `totalRecordingBytes()` (useRecording).
- **Tripwire test: known-heavy Tauri commands must stay `async`.** `heavy_commands_stay_async` in `src-tauri/tests/pitfall_invariants.rs` scans the source tree and fails if any command on a 29-entry heavy list (filesystem walks like `fs_grep`/`fs_delete`, subprocess probes like `ml_detect`/`wsl_home`, `pty_open`, …) is declared as a sync `pub fn`. Tauri runs non-`async` commands on the main thread, so the regression this guards — quietly dropping `async` in a refactor — reintroduces the app-wide input stalls fixed in 1.20.6 with no test failure and no visible error, which is exactly the failure shape tripwires exist for. The failure message tells the offender to route work through `modules::heavy()`; the list is the place to register new heavy commands.
- **Branch checkout from the source-control panel.** The branch chip in the panel header is now a dropdown: click it to list local branches (most recent commit first, current one checked) and select one to `git switch` to it — closing the "create exists (worktree -b), switch doesn't" gap. The menu stays open while the switch runs and on failure, so a dirty-tree conflict error is readable right where you clicked; success refreshes the whole panel (status, sections, per-branch accent color). Backed by two new IPC commands — `git_branches` (`for-each-ref refs/heads`, sorted by committer date) and `git_checkout_branch`, which validates the name against the branch list before invoking `git switch` (clear error for stale UI state, and no option-injection via a leading `-`). Remote branches are deliberately not listed — fetch first, then the local view is authoritative; creating a branch stays with the worktree section / terminal.
- **Go to line in the editor (Alt+G).** New `editor.goToLine` shortcut (rebindable, listed in the shortcuts dialog under Editor) opens CodeMirror's go-to-line panel in the focused editor pane — type a line number (or `+n`/`-n` relative, `n%` percentage, `:col` suffix, all supported by the stock panel) and Enter jumps and scrolls there. Inert outside editor tabs, so Alt+G still types normally in the terminal.
- **Editor language override dropdown.** The editor pane header (next to the word-wrap toggle) now shows the file's syntax language and lets you override it — pick from ~37 curated languages, "Plain Text" (highlighting off), or "Auto (…)" to return to extension/filename detection. Fixes the daily annoyances detection can't cover: extensionless scripts, config files with odd names, a `.conf` that's actually YAML. The override re-uses the existing lazy language loaders (a pack is only downloaded into the bundle chunk when first used, same as detection) and feeds the same compartment reconfiguration path, so switching is instant on open files; snippet expansion follows the override too. Session-only and per-path (`useLanguageOverrides` Zustand store) — deliberately not persisted until real usage says otherwise.
- **User-selectable default shell.** **Settings → General → "Default shell"** takes the full path of the shell to launch in new terminals (e.g. `/usr/bin/fish`), overriding the hardcoded detection order (login shell → `$SHELL` → `/bin/zsh` on unix; pwsh → Windows PowerShell → cmd on Windows). The override still gets shell integration when it's a shell Nexis knows (zsh/bash/fish, and PowerShell on Windows). Guardrails: the path is validated Rust-side (`sanitize_shell_override` in `shell_init.rs`) and a nonexistent path falls back to auto-detection with a logged warning instead of spawning a shell that instantly dies — the pitfall-#1 blank-terminal shape. WSL sessions ignore it (the distro's login shell applies inside the distro). Plumbing: new optional `shell` arg on `pty_open`, threaded through `openPty` from the `defaultShellPath` pref; applies to terminals opened after the change.
- **Terminal font weight setting.** **Settings → General → "Font weight"** (Light 300 → Bold 700, default Normal 400) sets the weight of regular terminal text — bold ANSI output keeps its own weight. Useful for thin-rendering Nerd Fonts on Linux and for anyone who prefers a heavier terminal face. Stored as `terminalFontWeight` (clamped to 100–900 in the setter), applied live to every pooled renderer slot via a new `applyFontWeight()` (with a refit, since glyph metrics change), and `writePref()`-synced across windows like every terminal pref.
- **Zen mode — hide the header and status bar with Alt+Z.** A new `view.zenMode` shortcut (rebindable; also in the command palette as "Toggle zen mode") collapses the window to nothing but the working surface — tabs, window controls, cwd pill, and status pills all disappear until toggled back. The chrome is hidden with `display: none`, not unmounted, so header search state and open find sessions survive the round-trip. Deliberately session-only (not persisted): relaunching into a chrome-less window with no visible way back would read as breakage. While zen is on there is no window-drag region (the header is the drag surface on the borderless chrome) — keyboard shortcuts, including Ctrl+Tab and the sidebar toggle, keep working. (Adopted from upstream terax-ai.)
- **Closing a terminal that's still running a command now asks first.** Closing a tab (X button, middle-click, Ctrl+W), a split pane (Ctrl+W with splits, the pane close button), or a pane whose shell is mid-command pops a "Process Still Running — closing will kill it" confirm instead of silently killing the child, mirroring the existing unsaved-editor-changes dialog. Busy detection rides the OSC 133 shell-integration markers Nexis already injects (the `inCommand` flag that also guards OSC 7 cwd spoofing): between `B`/`C` and the next `D`/`A` the shell is running something — vim and htop count, an idle prompt doesn't. The flag was lifted from per-slot-bind to session level (`sessionHasRunningCommand()` in `useTerminalSession.ts`) so it survives a background/foreground renderer-slot cycle, and it resets on respawn. Fail-open by design: without shell integration (no markers) the check can't tell busy from idle and closing stays silent. Opt out via the new **Settings → General → "Confirm closing a busy terminal"** toggle (`terminalConfirmCloseBusy`, default on, `writePref()`-synced). (Adopted from upstream terax-ai.)
- **Ctrl+Tab now switches tabs in most-recently-used order, Alt-Tab style.** Pressing Ctrl+Tab (`tab.next`) opens a small centered overlay listing tabs by recency; holding Ctrl and pressing Tab again advances the highlight (Ctrl+Shift+Tab / `tab.prev` goes backward, arrow keys work too), and *releasing Ctrl* commits the highlighted tab — so a single quick Ctrl+Tab toggles between your two most recent tabs, the most common case the old positional next-tab made a multi-press affair. Escape or window blur cancels without switching; clicking a row commits it. Tabs never activated this session (e.g. restored but not yet visited) are appended in tab-bar order so everything stays reachable, and if the user rebinds `tab.next` to a chord with no modifier the switcher degrades to an instant switch to the most recent other tab (there is no held key to release). MRU order is session-local state in `src/modules/tabs/lib/useMruTabSwitcher.ts`; the pure ordering rules live in `lib/mru.ts` with a unit-test suite (added to the coverage gate). Replaces the positional cycle — there is no setting to get the old behavior back. (Adopted from upstream terax-ai.)
- **Expansion packs (V1) — the feature surface is now core + opt-in packs.** The sidebar's panels split into a fixed core (terminal, editor, Files, Recent Files, Source Control, Activity queue, and the AI chat/agent) plus six toggleable packs: Navigation+ (outline, bookmarks), Code Tools (build, tests, debugger, symbol search, code review), AI Extras (refactor, prompt templates), Dev Tools (processes, ports, REPL, database, profiles, SSH), ML Lab, and Advanced (share, notes, snippets, release). A first-run dialog offers Bare-Bones / Standard / Everything presets (dismissing keeps everything on — upgrades change nothing), and **Settings → Features** has per-pack toggles plus the same presets, live-synced across windows via `writePref()`. Disabling a pack hides its rail items and panels (pinned rail entries survive in storage for re-enable) and deactivates pack-owned plugins (ML Suite) through `PluginHost`; a gated active view initially snapped back to the explorer silently — superseded in this same release by the in-place "enable pack" placeholder (see the V4 entry below). This is enablement gating, not installation — all code still ships; the future nexis-ml on-demand download will live under the ML Lab pack. Taxonomy is the single source of truth in `src/lib/packs.ts`, enforced by a test that every sidebar view is core or claimed by exactly one pack; rationale in `docs/vault/decisions/expansion-packs.md`.
- **Expansion packs (V2) — the command palette and keybindings now respect pack gating.** V1 gated the rail, the panel switch, and plugin activation, but a disabled pack's features stayed reachable through two side doors: the command palette still listed "Show activity (processes + agent queue)" with Dev Tools off, and the pack-owned keybindings — Send selection to REPL (Alt+Shift+R, Dev Tools), Refactor selection with AI (Alt+Shift+X, AI Extras), Toggle bookmark (Alt+D, Navigation+) — still fired and could open panels the rail no longer offers. `Shortcut` and `CommandDef` entries can now declare the pack that owns their target (`pack:` field, validated against the `src/lib/packs.ts` taxonomy by tests); while that pack is disabled the palette entry disappears, the binding is inert in `useGlobalShortcuts` (behaves as unbound — it doesn't shadow anything), and the shortcut row is hidden from both the shortcuts dialog and Settings → Shortcuts (customizations survive in storage for re-enable, like pinned rail entries). Core shortcuts are untouched; the new `packEnabled()` helper in `src/lib/packs.ts` is the single predicate for any non-sidebar-view gated surface.
- **Expansion packs (V4) — a gated panel now offers to enable its pack instead of vanishing.** When the active sidebar view's pack is disabled (a Settings toggle in another window, a first-run preset, or a decoupled `nexis:open-sidebar-view` request from a plugin/status pill/deep link), the panel slot renders a new `PackGatePlaceholder` — "This panel is part of the X pack", the pack's description, an **Enable** button (routed through `setEnabledPacks()`/`writePref()`, so it syncs across windows), and a "Show Files" escape hatch — replacing V1's silent snap-to-explorer and its silent dropping of open requests for gated views. Enabling restores the exact panel in place with no view switch. Alongside this, the sidebar now restores *any* last-open view across restarts (`readSidebarView` previously floored everything except Files/Source Control back to Files): heavy panels are lazy-loaded so restore stays cheap, and a restored view whose pack was disabled in the meantime lands on the placeholder instead of a broken panel — the exact "this tab needs the X pack" session-restore case from the roadmap.
- **Expansion packs (V3) — the nexis-ml engine download is now a consented, checksum-pinned install flow.** The ML Lab's standalone-engine download (the only thing Nexis ever downloads) previously fetched the GitHub *latest* release with no integrity check — its only vetting was running the unverified binary with `--version`. Decision (see `docs/vault/decisions/nexis-ml-artifact-pinning.md`): artifacts stay on the `rwetz/nexis-ml-rs` GitHub Releases, and each Nexis release compiles in an exact engine pin — release tag (`v0.8.0`), per-platform asset name, byte size, and SHA-256 — in `src-tauri/src/modules/ml.rs`. `ml_download` now derives the URL from the pin (the frontend can no longer supply one), hashes the bytes **before** they touch the managed dir or execute, refuses on mismatch, and post-install asserts `--version` reports exactly the pinned version. The panel's download button opens a consent step first: version, source, size, and the full pinned SHA-256, stated as "verified before it can run". New alongside it: an offline **"Install from a local copy"** path (`ml_install_local` — download the asset on another machine, point Nexis at the file; the same hash gate applies, so self-built engines still belong on PATH/venvs, which detection accepts unverified as before), an **uninstall** button with a disk-usage readout (`ml_uninstall` / `ml_engine_status`; removal falls detection back to venv/PATH engines), and unit tests covering the hash gate, the pin's well-formedness, and the no-URL IPC contract. Shipping a new engine now means bumping the pin (tag + hashes) in a Nexis release; the nexis-ml-rs release workflow should start publishing a `checksums.txt` so the pin can be cross-checked against CI output.
- **OSC 52 clipboard support — programs inside the terminal (tmux, vim, anything over ssh) can now copy to the system clipboard.** Write-only by design: an OSC 52 *read* request (`Pd` = `?`) asks the terminal to type the system clipboard back into the PTY, handing its contents to whatever program — or remote host — printed the sequence, so reads are consumed silently with no reply, unconditionally. Writes are gated behind a new **Settings → General → "Program clipboard access (OSC 52)"** toggle (`terminalOsc52Clipboard`, default on, routed through `writePref()` so it syncs live across windows and applies to open terminals without a rebind). The selection parameter (`c`, `p`, `s`, …) is ignored — everything targets the one system clipboard, matching most emulators — and base64 payloads over ~1 MB (~750 KB of text) are dropped as not-a-human-copy. Handler in `src/modules/terminal/lib/osc-handlers.ts` with tests covering the read-block, pref gating, malformed/oversized payloads, and UTF-8 decoding. (Adopted from upstream terax-ai 0.8.1.)

### Changed
- **The explorer icon sets no longer ship (or execute) as JavaScript.** The two Iconify JSONs behind file/folder icons — the pruned vscode-icons folder set (430 KB) and `@iconify-json/catppuccin` (300 KB) — were dynamic `import()`s, so Vite compiled each into a JS module chunk that the engine had to parse and evaluate as code. They're now `?url` asset imports: the raw `.json` files ship as static assets, fetched lazily off the critical path (same timing as before) and parsed with the native JSON parser. ~750 KB of "JS" leaves the bundle without regressing the lazy-load into main (the module statically imports only two URL strings). A failed fetch logs and clears the memoized load promise so the next `preloadIcons()` retries (the cached-rejected-promise lesson from pitfall #10); the icon-resolver tests shim `fetch` to serve the assets from disk in the node environment.
- **Active tab indication is now minimal: fill + text contrast only.** The brand-orange sliding indicator (with its glow shadow) above the active tab is gone, along with its measurement machinery (`ResizeObserver` + rect math in `TabBar.tsx`), and the base `TabsTrigger` focus ring (`focus-visible:ring-[3px]` + outline) is suppressed on tab triggers — on WebKitGTK it also fired on click-focus, double-ringing the tab you just selected. The active tab now reads by its `bg-accent` fill and full-foreground text against the dimmed inactive tabs. No accessibility loss: Radix tabs activate on focus (roving tabindex), so the active-tab style *is* the keyboard focus indicator.
- **Parked terminal renderer slots no longer hold WebGL contexts and DOM trees forever.** The renderer pool parks a slot when its tab is backgrounded, but every parked slot kept its live GL context (texture atlas included), xterm buffers, and DOM tree for the rest of the session — the exact shape of upstream terax's 914 MB webview-RSS bug, and more idle GL contexts also mean more context-loss events on the fragile Linux/NVIDIA drivers 1.20.5 fought. Now a parked slot loses its WebGL context after a 30 s grace period (`SLOT_REAP_GRACE_MS`), and grace-expired parked slots beyond one warm slot (`WARM_PARKED_SLOTS`) are disposed entirely; adopting a tab re-attaches WebGL on the spot, and the warm slot keeps instant tab-switching. Deliberate reaping goes through the same teardown path as the settings toggle, so it never counts toward the 1.20.5 `webglLossCount` thrash heuristic (that's for *involuntary* losses), and `applyWebglPreference` skips resurrecting reaped slots. Slot ids are now monotonic instead of index-based so `data-nexis-slot` stays unambiguous after a disposal. (Terax notes §2.1/§2.2.)
- **The `motion` animation library is gone — every animation is now plain CSS.** motion ran its spring/tween loops in per-frame JS on the main thread; CSS transitions and keyframes composite on the GPU side of WebKitGTK and cost nothing when idle, and the dependency (plus its dedicated lazy chunk and the `src/lib/motion.ts` tween presets) drops out of the bundle. The two non-trivial ports: the TabBar's sliding active-tab indicator was a motion `layoutId` shared-layout element and is now a single measured span following the active trigger via a CSS `left`/`width` transition (re-measured by a `ResizeObserver`, since tab labels change width live), and the AI shimmer label is now the `nexis-shimmer` keyframes in `globals.css`. Everything else (`AnimatePresence` fades/slides in the AI panel, input bar, mini window, explorer/header search, status-bar controls, kbd hints, chat code blocks) became `tw-animate-css` `animate-in` utilities — exit animations were dropped where they existed; entrances match the old timing. motion's `MotionConfig` honored the OS reduced-motion setting app-wide; a global `prefers-reduced-motion` rule in `globals.css` keeps that promise for both the `animate-in/out` utilities and the shimmer. (Terax notes §2.3 — upstream's equivalent pass was their 0.8.0 #710.)
- **Criterion benchmark harness for the Rust hot paths** (`src-tauri/benches/hot_paths.rs`, run with `cargo bench --features bench-internals`): PTY reader `DaFilter` throughput (plain-text fast path vs ANSI-dense worst case), `git status --porcelain=v2` parsing at 5k files including the lossy-UTF-8 conversion (pitfall #13 path), and end-to-end `fs_grep` over a synthetic 200-file tree. Exists so the ROADMAP "Selective TS → Rust migration" item and any PTY/grep tuning start from numbers, not guesses. The `bench-internals` cargo feature only re-exports internals to the bench target and is never enabled in shipping builds (dev-dependency + `required-features` double-lock). Alongside it: two non-shipping cargo profiles — `profiling` (release + symbols, thin LTO, for perf/flamegraph) and `release-fast` (no LTO, 16 codegen units, for iteration without the fat-LTO wait; the size-first shipping profile is untouched) — and three new workspace clippy lints borrowed from Zed (`redundant_clone`, `dbg_macro`, `todo`; CI's `-D warnings` promotes them to errors). `redundant_clone` immediately caught six real paper-cuts, now fixed: needless clones per searched file in `fs_grep`, per status snapshot and commit-file diff in git operations, and needless `AppHandle`/`Arc` clones in the git path-guard error, ML waiter threads, and the DAP reader spawn. (Zed notes §2.1–2.3.)

## [1.20.6] — 2026-07-12

A performance release. The headline: heavy Tauri commands no longer run on the main thread, so a workspace-wide grep from the AI agent, a `node_modules` delete, or the explorer's refresh poll can't stall terminal keystrokes or freeze the window anymore — and PTY input got a dedicated writer thread so a flow-stopped shell can't wedge the app on paste. Startup also got measurably lighter (2.8 MB → 2.1 MB of preloaded JS; main chunk 978 KB → 813 KB) by fixing four silently-defeated code-splits and lazy-loading the Settings/ML/Database/Debugger panels, and the biggest steady-state render sinks (per-token AI streaming re-renders, the editor minimap, always-on background animations) were throttled, memoized, or paused. Rounding it out: the Linux borderless-window fixes and editor/zoom/LSP fixes that landed since 1.20.5.

### Changed
- **Performance sweep: heavy Tauri commands moved off the main thread — no more app-wide stalls while the AI agent greps or the explorer refreshes.** Tauri runs non-`async` commands on the main thread; while one runs, the UI event loop and every queued IPC call (including terminal keystrokes via `pty_write`) wait behind it. The git module already did this correctly (`async fn` + `spawn_blocking`), but ~25 other commands were plain sync `pub fn` — including `fs_grep` (parallel regex walk over the whole workspace), `fs_search`/`fs_list_files`, `fs_read_file`/`fs_write_file`/`fs_read_file_ai`, `fs_delete` (recursive — deleting `node_modules` froze the app), `fs_read_dir`/`list_subdirs` (polled every 3 s by the explorer), shell history load/search, `shell_session_open`/`shell_bg_spawn` (process spawn; WSL cwd resolution can take seconds on a cold distro), `ml_detect`/`ml_env` (probe subprocesses that import torch — seconds each), `ml_gpu_probe`, `wsl_home`, and `list_crash_reports`. All now run on the blocking thread pool via a shared `modules::heavy()` helper (`src-tauri/src/modules/mod.rs`); commands that only lock a map (`pty_resize`, `pty_close`, `shell_bg_*`, …) intentionally stay sync. State-taking commands (`shell_session_open`, `shell_bg_spawn`) re-fetch state from an `AppHandle` inside the closure, following git/commands.rs. No frontend changes needed — the JS `invoke` contract is identical.
- **Terminal input writes can no longer freeze the app on a full PTY pipe.** `pty_write` did a blocking `write_all` to the PTY master on the main thread; if the child stopped reading (Ctrl+S flow control, a stopped process) the kernel pipe buffer filled and a large paste blocked the entire app until the pipe drained. Each PTY session now has a dedicated `nexis-pty-writer` thread fed by a FIFO channel: `pty_write` just enqueues (never blocks), byte order is preserved by the channel (a naive `spawn_blocking` per write could reorder rapid keystrokes), and the thread exits when the session drops or the pipe closes. The writer thread is covered by the existing `ThreadSpawnGuard` teardown, and the input queue is unbounded but bounded in practice by typing/paste volume (output already has the 4 MiB backpressure cap).
- **Startup JS payload cut 25% (2.8 MB → 2.1 MB preloaded) by fixing four defeated code-splits.** The Vite config carefully splits lazy chunks, but static imports had silently re-eagered them: (1) `useWhisperRecording` statically imported `createOpenAI`, dragging the OpenAI SDK into startup — now dynamic-imported at transcription time, matching agent.ts's per-provider lazy imports; (2) `ai-elements/message.tsx` statically imported `Streamdown`, loading the entire remark/rehype/micromark pipeline (~480 KB) before the first terminal paints even for users who never open the AI panel — now `React.lazy`, loaded on the first rendered assistant message; (3) `rendererPool.ts` statically imported `WebglAddon` (~110 KB GPU pipeline) despite its dedicated chunk — now dynamic-imported in `attachWebgl()` with post-await re-validation so a preference toggle during load can't double-attach; (4) `tailwind-merge` + `clsx` (the `cn()` helper used by every component) had been colocated by Rollup *inside* the lazy streamdown chunk, forcing it into the preload set anyway — `vite.config.ts` now pins them (plus Vite's preload/commonjs helper virtual modules, same hazard) to a small always-loaded `ui-utils` chunk.
- **Heavy, rarely-open panels now lazy-load instead of shipping in the main chunk** (main: 978 KB → 813 KB): the Settings dialog (with all its sections incl. the 950-line Models section — mounted only after first open, then kept mounted so the close animation still plays), the ML panel (2,100+ lines; the ML plugin now imports the status pill from concrete files instead of the module barrel so the panel actually splits), the Database panel, and the Debugger panel + toolbar — all via the same `lazy()`/`Suspense` pattern as the Markdown/Notebook/Image stacks.
- **AI streaming re-renders throttled.** None of the four `useChat` consumers (panel, floating panel, mini window, run bridge) passed `experimental_throttle`, so every streamed token re-rendered all of them — and several `useMemo`s keyed on `messages` (pending-approval count, file-mutation fingerprint, the context-indicator token estimate) re-scanned the entire conversation per token. A shared `STREAM_THROTTLE_MS = 50` caps UI updates at 20/s — imperceptible next to token cadence, ~5-10× less render work on long conversations.
- **Editor minimap no longer rebuilds the whole document view 5×/second.** The minimap extracted every line of the document as strings and re-rendered one `<div>` per line on a 200 ms interval *and* on every scroll event — on a 10k-line file, easily the biggest editor-side CPU sink. Line extraction is now memoized on CodeMirror's immutable doc identity (only re-runs when the document actually changes), the strips render through a `memo` component keyed on that stable array, scroll updates are rAF-coalesced and only move the viewport indicator, and idle interval ticks bail out without re-rendering.
- **Animated backgrounds pause while the window is hidden, and DotField idles at zero cost.** All five animated backgrounds (Aurora, Particles, Threads, DarkVeil, DotField) ran unconditional `requestAnimationFrame` loops — constant GPU burn while minimized, since WebKitGTK doesn't reliably suspend hidden rAF. A shared `runRafLoopWhileVisible` helper (`src/components/ui/backgrounds/rafLoop.ts`) gates every loop on `visibilitychange`, mirroring what the background-image path already did. DotField additionally: folds its separate 50 Hz mouse-speed `setInterval` (which kept firing while hidden) into the rAF tick, caches its fill gradient instead of rebuilding it every frame, and skips clear+redraw entirely once the field is fully at rest (no cursor engagement, no wave/sparkle) — an idle visible window now costs ~zero instead of a full canvas repaint per frame. Particles clamps its time delta so the animation doesn't leap after a pause.
- **ML panel's 1 Hz elapsed-timer tick now only runs while a run is actually training** (starting/running/cancelling and not paused) — it previously re-rendered the whole 2,100-line panel every second even for a finished run left open in the sidebar.

### Fixed
- **Linux: window couldn't be resized by dragging its edges (and showed no resize cursor there).** Fallout from the 1.20.5 borderless chrome: the invisible resize-grab zone around a normal window is part of GTK's client-side decoration shadow, so `decorations: false` + `shadow: false` (`tauri.linux.conf.json`) removed it entirely — the compositor had nothing to hit-test at the window edges, leaving KWin's Super+Right-drag as the only way to resize. (Windows was never affected: tao gives undecorated windows native `WM_NCHITTEST` resize borders; GTK has no equivalent.) A new `WindowResizeEdges` component (`src/components/WindowResizeEdges.tsx`, Linux-only) restores the affordance in the webview: invisible fixed-position strips along the edges (5px) and corners (14px) that show the matching resize cursor from the Tailless Smooth set and hand the gesture to the compositor via `startResizeDragging()` on pointer-down. The strips mount at the App shell root, deliberately *outside* `.zoom-content`, so app zoom can't scale the hit areas away from the real window edges; they unmount while maximized/fullscreen so screen-edge UI (tabs, scrollbars) keeps its clicks, and they carry an explicit `pointer-events-auto` so Radix modal dialogs (which set `pointer-events: none` on `<body>`) don't silently disable resizing while open. — resize cursor over the file explorer, grabbing cursor over the editor.** Two mechanisms, both worst on Linux/Wayland: (1) react-resizable-panels injects a global `*, *:hover { cursor: <resize> !important }` stylesheet while a handle is hovered or dragged; WebKitGTK re-evaluates the cursor lazily when that rule toggles, and a dropped pointer event leaves it applied outright — so the resize cursor bled over the UI next to a handle (the file tree sits 4px from the sidebar handle). The global rule is now disabled (`disableCursor` on every panel group) and the handle element itself carries the resize cursor via `[data-slot="resizable-handle"]` CSS. Tradeoff: the cursor no longer shows as resize in the library's few-px grab zone *around* a handle, only on the handle. (2) The tab-reorder and file-explorer move drags set a document-wide grabbing cursor cleared on window `mouseup` — but those listeners take no pointer capture, so releasing the button outside the window (or a mid-drag focus steal by the native drag region / Alt-Tab) meant the mouseup never arrived: the drag stayed armed and the grabbing cursor stuck until some future click. Both drags now self-heal: a `mousemove` arriving with no buttons held ends the drag (tab drag commits like a normal drop; the explorer drag cancels rather than dropping files onto whatever is under the pointer), and a window `blur` cancels outright. The explorer drag also uses the custom grabbing PNG cursor now, matching the tab drag.
- **Terminal exit-status gutter bar painted down the entire terminal instead of one line.** The OSC 133 exit decoration (`addExitDecoration` in `src/modules/terminal/lib/osc-handlers.ts`) overrode the decoration element's height with `100%`, which resolves against xterm's decoration container — the whole screen — not the row, so every prompt grew a full-height 2px green/red line hugging the left edge (easily mistaken for an active-pane indicator). xterm already sizes decoration elements to exactly one cell row; the override is simply removed, so the bar now accents only the command's prompt line as intended.
- **LSP never activated for tabs restored at startup (empty Problems counts / no inline diagnostics until the tab was reopened).** `EditorPane` activated LSP once, when the file finished loading — but the workspace root it needs comes from the chat store's `live` registry, which starts as a no-op (root = `null`) until App re-registers it after `explorerRoot`/`launchCwd`/`home` hydrate. Restored tabs usually lost that race, `activateLsp` returned `null`, and nothing ever retried — so a reload silently killed diagnostics, hover, completion, and go-to-definition for every restored editor. The pane now subscribes to the live workspace root (a primitive selector, pitfall-#14 safe) and re-runs LSP activation when it appears or changes.
- **CodeMirror lint/hover tooltips rendered as white boxes on dark themes.** None of the bundled editor themes style CM's tooltip layer, so diagnostic hovers fell back to the base theme's light-gray background — near-unreadable white rectangles on a dark UI. The shared editor theme now paints `.cm-tooltip`/`.cm-diagnostic` with the app's popover palette.
- **Editor clicks landed on the wrong line whenever app zoom ≠ 100%.** App zoom (Ctrl+= / Ctrl+- / Ctrl+0) is implemented as CSS `zoom` on the main content, and WebKitGTK's caret-from-point APIs — which CodeMirror uses to turn a mouse click into a document position — ignore an ancestor CSS `zoom`. The click's coordinates and the editor's geometry then disagree by exactly the zoom factor: at zoom 1.4, clicking line 13 put the cursor on line ~19 (13 × 1.4), with the offset growing further down the file. Because `zoomLevel` persists in preferences, one accidental Ctrl+= left the editor mis-clicking across restarts. Every CodeMirror instance (editor, git diff, AI diff — the terminal and REPL were already `zoom-exempt`) is now exempted from layout zoom via `.zoom-content .cm-editor { zoom: calc(1 / var(--app-zoom)) }`, and app zoom reaches the code by scaling the shared theme's font-size (`calc(13px * var(--app-zoom))`) instead — so zoom still visibly zooms the code, but click coordinates stay 1:1. Known limitation: in-editor popups (autocomplete list, LSP hover) no longer scale with app zoom, since they live inside the exempted subtree. Documented as CLAUDE.md pitfall #15 with a tripwire in `src/lib/pitfall-guards.test.ts` guarding both halves of the fix.

## [1.20.5] — 2026-07-08

A Linux-focused release that makes Nexis genuinely smooth on NVIDIA + Wayland. It removes the WebKitGTK-on-NVIDIA render lag (the DMABUF renderer and per-frame `backdrop-filter` repaints), fixes a theme-switch crash and a terminal WebGL context-loss thrash loop (with its frozen ghost cursor), and finally gives Linux the borderless window chrome — no double title bar, real rounded corners — that Windows already shipped. All changes are `#[cfg(target_os = "linux")]`/Linux-attribute scoped; macOS and Windows behavior is unchanged.

### Fixed
- **Terminal lag on Linux/NVIDIA from a WebGL context-loss thrash loop.** On some WebKitGTK + NVIDIA setups the terminal's xterm.js WebGL renderer loses its GL context immediately and repeatedly. The recovery path in `src/modules/terminal/lib/rendererPool.ts` re-attached WebGL 250 ms after every loss — so a machine that loses the context on every attach got stuck flipping the terminal between the GPU and DOM renderers ~4×/second, which is far laggier than just using the DOM renderer (the editor, which uses no WebGL, stayed perfectly smooth — a dead giveaway). `attachWebgl`'s `onContextLoss` now counts rapid losses: after `WEBGL_MAX_LOSSES` (3) within a stability window it gives up and stays on the DOM renderer for that slot instead of thrashing. A genuine one-off loss (sleep/wake, GPU reset) still recovers — the counter resets after `WEBGL_STABILITY_RESET_MS` (60 s) of stability — and machines where WebGL is stable (Mesa, etc.) are unaffected. Toggling the "Hardware-accelerated rendering" setting back on clears the auto-give-up for a fresh attempt. The manual toggle in Settings → General remains as an explicit override. As part of this, the context-loss path was fixed to fully tear down the abandoned WebGL layer (shared `hardTeardownWebgl` helper): it previously cleared its canvas tracking *without* releasing the GL contexts or zeroing the canvases, so the dead GPU layer kept painting its last frame — a **frozen ghost cursor** — on top of the live DOM renderer (and leaked a canvas per loss). The give-up path now also forces `term.refresh()` so the DOM cursor and cells repaint clean.
- **Theme switch crashed the whole window on Linux/NVIDIA.** Changing the app theme (or light/dark mode) ran the palette swap inside a `document.startViewTransition` crossfade, which makes WebKitGTK capture a full-page **GPU snapshot** to composite the animation. On the NVIDIA proprietary driver that snapshot crashes the WebKit web process outright — a silent renderer death (no Rust panic, so nothing lands in `~/.cache/nexis/crash/`) that takes the window down on every theme change. `withViewTransition()` in `src/modules/theme/ThemeProvider.tsx` now short-circuits to an instant swap on Linux (same fallback it already used for `prefers-reduced-motion`), so the theme changes without the crossfade. macOS/Windows keep the animation. Same underlying WebKitGTK-on-NVIDIA compositing weakness as the DMABUF lag below.
- **Linux render lag on NVIDIA GPUs — WebKitGTK DMABUF renderer now disabled where it hurts.** WebKitGTK 2.44+ composites through a DMABUF-backed accelerated path by default; on the **NVIDIA proprietary driver** that path is buggy and slow — tearing, stutter, and high CPU on *every* frame (terminal scroll, editor, the whole webview), which is the "a tad laggy" feeling on an otherwise fast machine (e.g. an RTX 4070 on KDE Wayland). `tune_linux_webkit()` in `src-tauri/src/lib.rs` now sets `WEBKIT_DISABLE_DMABUF_RENDERER=1` **before** the webview forks its WebKit processes, so compositing falls back to the reliable GL/EGL path. It's scoped tightly: the switch only flips when the proprietary driver is actually loaded (`/proc/driver/nvidia/version` or `/dev/nvidia0` present) — Mesa (Intel/AMD) drives DMABUF well and is *faster* with it on, so those users are untouched — and it never clobbers the env var if you've already exported it yourself. macOS/Windows unaffected (`#[cfg(target_os = "linux")]`).

### Changed
- **Linux gets the custom borderless window chrome (no double title bar, real rounded corners).** Linux had no platform config override, so it fell back to the base window config — decorations on — and KDE/GNOME drew their **native server-side title bar** *on top of* Nexis's own header (two title bars), while the opaque rectangular window squared off the corners the app tries to round. A new `src-tauri/tauri.linux.conf.json` mirrors the existing `tauri.windows.conf.json` (`decorations: false, transparent: true, shadow: false`), so the native bar is gone and the window is transparent — letting the already-active `data-chrome="borderless"` CSS (12px `border-radius` on `#root`) render as the actual window corners. Drag (`data-tauri-drag-region` in the header) and the custom min/max/close controls were already wired for Linux; they just needed the undecorated window. On KDE Plasma, KWin draws a *server-side* title bar for GTK/WebKit windows even when the app requests `decorations: false` (a double bar); `tune_linux_webkit()` now sets `GTK_CSD=1` (forces client-side decorations so KWin defers to the app) and the Tauri `setup` hook re-asserts `set_decorations(false)` after the webview initializes, since webkit2gtk can reset the window hint during startup.
- **Linux: `backdrop-filter` blur dropped to cut per-frame paint cost.** WebKitGTK re-composites the blurred backdrop region every frame — cheap on Mesa, expensive on the NVIDIA proprietary driver, and worst on the sticky panel/table headers and the source-control side panel, which repaint on every scroll. On Linux only (keyed off a new `data-os="linux"` attribute set in `src/main.tsx`), `src/styles/globals.css` now neutralizes every `backdrop-blur*` surface. All ~22 sites that used it already carry an opacity-backed background (`bg-card/80`, `bg-popover/90`, `bg-black/30`, …), so overlays, popovers, and headers stay legible — they just render as solid translucency instead of frosted glass. macOS/Windows keep the blur.

### Security

## [0.7.4] — 2026-05-23

### Fixed

**Rust backend**
- **PTY thread panic propagation** — All `.lock().unwrap()` calls on the shared `pending` mutex in `session.rs` (reader, flusher, waiter threads) now use `.unwrap_or_else(|e| e.into_inner())`. A panic in one thread no longer poisons the mutex and silently kills output in all other threads.
- **`pty_close` killer-lock panic** — `s.killer.lock().unwrap()` in `pty_close` replaced with `if let Ok(mut k) = s.killer.lock()`. A poisoned killer mutex (child process had already crashed) no longer panics the Tauri worker thread.
- **`pty_close` thread-spawn panic** — `thread::spawn(...).expect("spawn pty drop thread")` replaced with `.map_err(...)? `. Out-of-memory or thread-limit conditions now return an error to the frontend instead of aborting the process.
- **Git stdout silent UTF-8 data loss** — `git_stdout_line_opt` and `git_stdout_lines` in `process.rs` used `std::str::from_utf8(&output.stdout).unwrap_or("")`, which discards all output on invalid UTF-8 (e.g. Latin-1 encoded commit messages, binary filenames). Changed to `String::from_utf8_lossy(...)` to replace invalid bytes with `U+FFFD` instead of returning empty results.

**TypeScript / Frontend**
- **Shell agent session permanently broken after open failure** — `getSessionShell()` in `tools/shell.ts` cached rejected promises in `sessionShells`. If `shellSessionOpen` failed, every subsequent `bash_run` in that session re-threw the original error forever. The promise's `.catch()` handler now deletes the map entry before re-throwing, so the next call retries cleanly.
- **`approxBytes` throws on circular tool output** — `JSON.stringify(part.output)` in `compact.ts` throws a `TypeError` on circular object references. Replaced with a `safeJsonLength()` wrapper that catches the exception and returns a conservative estimate, preventing context compaction from crashing mid-conversation.
- **`dirname()` wrong result for Windows drive roots** — `dirname("C:/file.txt")` returned `"C:"` instead of `"C:/"`, breaking any path-based git or navigation operation for files at the drive root. Fixed by special-casing `idx === 2 && path[1] === ':'` to preserve the trailing slash. Also fixed `idx === 0` to return `"/"` (Unix root) instead of the full path.
